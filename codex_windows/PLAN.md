# Codex Windows 작성 계획

현재는 문서 골격 단계입니다. Windows skill 구현·실행 코드·개인 config·설치는 미실행입니다. 완료 상태는 [TODO](TODO.md), 문제는 [ISSUE](ISSUE.md), 직접 검사는 [REVIEW](REVIEW.md)에 연결합니다.

## 1. Linux 원문 보존

[Linux 모음](../codex_linux/README.md)의 19개 원문·코드·예시·참조·과거 기록을 보존합니다. 경로 이동 전후 bytes와 연결을 확인하고 원문을 축약·통합하지 않습니다. 완료 조건은 이동 전후 보존 근거와 활성 안내의 링크 정합성입니다. 과거 기록의 경로는 당시 상태로 구분하며 삭제하지 않습니다.

## 2. Windows 작업 조건 확인

PowerShell·실제 Python·UTF-8 읽기/쓰기/출력·현재 저장소 지침을 확인합니다. 개인 홈 설치와 저장소 구현 작업을 구분합니다. Bash·fcntl·POSIX 소유·symlink·ACL의 적용 범위를 정합니다. 필요한 Windows 대체 동작이 확인되지 않으면 해당 기능을 미검증으로 남깁니다.

## 3. 우선 skill 선택

실제 Windows 작업 예시를 기준으로 필요한 skill을 선택합니다. 후보와 순서는 [skills 안내](skills/README.md)에서 관리하며 기존 19개를 자동 복제하지 않습니다. 완료 조건은 각 후보의 목적·적용 조건·필수 자료·검증 사례와 선택 이유입니다. 선택하지 않은 Linux 원문도 보존합니다.

## 4. 전용 코드와 동봉 자료

선택한 skill의 Windows 호환 본문·필수 참조·도구를 독립 폴더로 작성합니다. Linux 원문 대응과 플랫폼 변경 이유를 기록합니다. UTF-8을 코드에 명시하고 네이티브 PowerShell·Python 호출을 확인합니다. Windows skill에서 다른 skill의 별도 설치를 요구하지 않도록 필수 자료를 동봉합니다.

## 5. Windows 행동과 도구 검증

[검증 안내](verification/README.md)에 따라 새 TEMP fixture에서 정상·실패·오류 전파·한국어 문서를 검사합니다. 실제 최종 입력 해시와 결과를 보존합니다.

대표 모델 행동·Codex 발견·메타데이터·동시 잠금은 각 범위를 구분합니다. 실행하지 않은 검사를 통과로 기록하지 않습니다.

## 6. yunli 게시

구현·문서·관련 검사를 마친 검토 가능한 변경만 yunli에 push합니다. 완료·부분 검사·미실행과 복구 범위를 함께 기록합니다.

개인 홈·운영 적용은 게시에 포함하지 않습니다. 미게시 복구는 이번 diff만 대조하고 게시 후 복구는 검토한 revert를 사용합니다.

## 7. 사용자 검증

yunli의 검토 대상과 사용 조건을 사용자에게 제공합니다. 사용자 검증 결과를 기록하고 필요한 보완·재검사를 수행합니다.

사용자 검증이 끝나기 전에 main 반영을 완료 처리하지 않습니다.

## 8. main 반영과 push

사용자 검증을 마친 변경을 main에 반영·push하고 결과를 확인합니다. 게시 결과와 개인 설치·환경 검증 결과는 별도로 기록합니다.
