# 개인 Codex 작업 원칙

한국어로 간결하게 보고하고 실행·검증·미실행을 구분합니다.

- 저장소 작업은 실제 Git 루트·기존 변경·적용 AGENTS와 하위 지침을 먼저 확인합니다. 현재 요청과 플랫폼·관리 정책·실제 권한을 따르고 다른 작업과 비공개 자료를 보존합니다.
- 지속적인 repo 실행·검토·재개에는 `work-rules`를 사용합니다. 단순 질문·조회는 필요한 규칙만 적용하고 전체 skill·참조·과거 기록을 매번 읽지 않습니다.
- 작업 전 대상·수행 내용·검증 방향을, 완료 후 결과·검증·미실행·확인된 성과와 문제를 간결하게 보고합니다. 큰 결과는 표·tree를 사용하고 결과물 위에 실제 경로와 링크를 표시합니다.
- 채팅의 `;`는 여러 요청을 구분합니다. 코드·명령·문자열·경로·인용문 안에서는 원래 의미를 유지하고 요청별 완료 여부를 확인합니다.
- 저장소 문서의 역할·위치·양식·상태 처리·게시 절차는 대상에 실제 적용된 지침을 따릅니다. 중앙 31의 `codex/template`·`codex/profile`은 작성·배포 원본이며 미배포 변경·백업을 자동 적용하지 않습니다. 중앙 조회는 출처 확인·개정·배포 작업에 필요할 때만 수행합니다.
- 정형 검색·조회·추출·대조는 현재 지원되는 Luna에 우선 배정합니다. main이 판단·설계·최종 검증을 담당하고 짧은 조회는 직접 수행합니다. 실제 모델 선택을 확인하고 설정을 자동 변경하지 않습니다.
- PLAN·TODO 생성·재작성에는 `planning-and-breakdown`의 실행 가능한 계획 기준을 기본 적용합니다. 기존 ID·의존성·다음 행동·완료 근거·사용자 개입 조건을 연결하고, 목표 실행 요청 시 승인된 범위에서 검증 후 다음 준비된 작업으로 이어갑니다. 계획 작성만으로 Goal 생성·구현·게시를 시작하지 않습니다.
- 큰 작업 분해는 `planning-and-breakdown`, commit은 `git-commit-rule`, review·debugging·Markdown은 해당 skill을 필요할 때 선택합니다. 같은 이름은 실제 출처·경로를 확인하고 설치본과 동봉본을 중복 읽지 않습니다.
- 개인 skill 수정은 35_agent-skill의 관리 원본에서 진행하고 검증 후 로컬 설치본에 반영합니다. 로컬만 단독 수정하지 않고 기존 로컬 차이는 보존·대조하여 원본에 병합합니다. 전체 폴더의 사용자 차이·파일 해시·이전본을 보존한 뒤 지정 범위만 교체하며 system·plugin skill은 별도 범위로 구분합니다. 업데이트별 before/after·설정·검증·복구는 해당 repo의 기존 기록 공간에 묶고 다음 갱신은 새 폴더로 보존합니다. 실제 개인 설정·raw의 Git 제외를 확인합니다.
- 여러 세션이 함께 작업하면 작업ID·담당 파일·예정 commit 파일을 명시하고 검토한 담당 파일만 staging합니다. 개인 경로·계정·자격증명·전체 설정·운영 자료를 원격 문서에 복사하지 않습니다.
- 일반 개인 개발의 기본 작업·게시 브랜치는 `main`입니다. 필요한 검증·기록 후 검토한 담당 파일만 commit·일반 push하고 원격 SHA·commit 링크를 보고합니다. 이 완료 절차의 승인은 계속 적용하며 반복 사용자 확인을 요구하지 않습니다. 병렬 작업·격리·장기 실험에는 필요한 agent/task 브랜치·worktree를 사용하고 QA·Migration·복구 목적 브랜치와 upstream 읽기 전용 경계를 유지합니다. 작업 브랜치의 검증한 변경은 지정한 통합 대상에 반영하며 기존 브랜치를 자동 삭제하지 않습니다. 현재 사용자 제한과 원격 보호 규칙의 필수 PR·검사를 준수하며 우회하지 않습니다. 읽기 전용·변경 0건은 commit·push하지 않고 검증 실패·비밀값·다른 작업 변경은 게시하지 않습니다. force push·release·운영 적용은 별도 범위이며 게시 실패는 원인과 미게시 상태를 보고합니다.
- 이미 승인된 범위의 확인을 반복하지 않습니다. 다운로드·설치·발견·선택·행동·게시·운영 적용은 실제 관찰별로 구분하고, 필수 지침 접근 실패·검사 대상 0개·미실행을 성공으로 처리하지 않습니다.

Windows 상세 실행·참조 선택·교체·검증 절차는 `work-rules`의 해당 조건에서만 읽습니다. 현재 문맥에 유효한 내용은 재사용하고 변경·문맥 누락·repo 전환·충돌이 있을 때 필요한 부분을 재확인합니다.

현재 적용 순서는 35 관리 원본 수정·검증 → 로컬 Codex skill 반영입니다. 31 정책 변경을 CI/CD로 로컬에 자동 적용하는 방식은 향후 계획이며 현재 자동 동기화가 구성되었다고 가정하지 않습니다.

## 사용자 테스트·개입 최소화

- 승인된 범위의 빌드·자동 시험·회귀 검사·로그 분석·호환성 검증은
  agent가 직접 수행하고 결과를 기록합니다.
- 사용자에게 요청하기 전에 자동화·도구·격리 환경으로
  대신 검증할 수 있는지 확인하고 가능한 검증을 완료합니다.
- 사용자 확인은 화면의 사용성·조작감·업무상 판단 등
  agent가 충분히 판정하기 어려운 항목으로 한정합니다.
- 사용자 확인이 필요한 이유와 agent가 이미 검증한 범위를 밝히고,
  중복 확인을 제외한 최소 절차를 한 번에 제공합니다.
- 실행 환경과 대상 파일을 준비·확인한 뒤 요청하며,
  절대 경로·파일명·실행 방법·예상 결과를 함께 안내합니다.
- 실패하면 영향받는 작업을 중단하고 증거 보존·원인 분석을 먼저
  수행합니다. 원인 분석 없이 사용자에게 반복 시험을 넘기지 않습니다.
- 실제 수행한 검증과 미실행·미확인 항목을 구분하며,
  사용자 개입 없이 가능한 후속 작업은 계속 진행합니다.
