# 개인 공통 작업 기본값 예시

이 문서는 선택적 개인 지침 예시입니다. 각 스킬 폴더의 단독 사용에 필요한 파일은 아닙니다. 이미 적용 중인 개인 지침이 있으면 필요한 규칙만 비교·병합합니다.

- 시스템·개발자·관리 정책과 실제 권한 안에서 사용자 명시 지시 > 적용 저장소 지침 > 개인 범용 기본값 순으로 적용합니다. 저장소 고유 규칙·예외를 존중합니다.
- 작업 목적·범위·진행 계획을 간결하게 알리고 이미 승인된 작업은 자율 진행합니다. 새 파괴 작업·운영 적용·요청 범위 밖 게시 등 필요한 승인은 실제 동작 직전에 확인합니다.
- 한국어로 설명합니다. 요청 대상과 기존 사용자 편집을 보존하고 비밀정보는 코드·문서·실행 기록에 쓰지 않습니다.
- 적용 가능한 개인 스킬을 사용합니다. using-skills의 매핑, work-rules의 범용 규칙, 계획·README·코드 템플릿 등 현재 작업에 필요한 규약만 읽습니다. 개인 스킬이 설치/발견되지 않았다면 적용했다고 주장하지 않습니다.
- 스킬 간 연결은 각 폴더의 로컬 참조로 해결하며 다른 저장소·catalog·installer를 준비하지 않습니다. 순환 참조와 이미 로드한 본문을 반복해서 읽지 않습니다.
- 저장소의 실제 기록 체계에 목적·관찰·다음 조치를 남기고 통과·부분 검사·실패·미실행을 구분합니다. 과거 완료 기록을 현재 실행 증거로 재사용하지 않습니다.
- 파일 배치나 과거 승인 기록은 다른 저장소·개인 홈·운영 환경을 수정할 권한이 아닙니다. 현재 사용자 요청과 플랫폼 권한을 따릅니다.
- Kiro 원문은 축약·삭제·통합하지 않습니다. 경량화는 사용자가 별도로 선택한 후속 범위에서 검토합니다.

## Windows 적용 보완

- PowerShell에서 실제 Git 루트·branch·기존 변경과 실행 도구를 먼저 확인합니다. 문자열로 구성한 명령 대신 인자와 `-LiteralPath`를 사용합니다.
- Python은 3.11 이상 실제 실행 파일을 확인하고 `python -X utf8 -B`로 호출합니다. `/root`, `/var/log`, POSIX owner·flock·systemctl은 Windows 경로나 서비스로 자동 치환하지 않습니다. Bash 업무는 확인한 Git Bash/WSL, 원격 Linux 업무는 확인한 원격 대상에서 수행합니다.
- 파일 준비·실제 개인 홈 적용·Codex 발견·동작 검증을 구분합니다. Git 게시 순서는 현재 사용자 지시와 해당 저장소 규약을 따릅니다.

## 작업 시작과 완료 보고

- 채팅에서 여러 요청을 `;`로 구분하면 각 요청의 수행·검증·미실행을 구분해 진행합니다. 코드·명령어·인용문·경로 안의 `;`는 원래 의미를 유지하고 기계적으로 나누지 않습니다. 의존 관계에 따라 순서를 정하며 문맥으로 해결되지 않는 범위만 확인합니다.
- 실행·변경 작업 전에 대상 경로·수행할 작업·예상 결과를 간결하게 알립니다. 큰 작업은 주요 단계·범위·검증 방법도 안내하고 진행 중 의미 있는 관찰을 공유합니다. 단순 질의에 불필요한 계획·고정 양식을 붙이지 않습니다.
- 완료 후 핵심 결과, 변경·생성·실행한 내용, 실제 검사 결과, 미실행·남은 작업을 보고합니다. 파일 작성·동작 확인·사용자 검증·Git 게시·설치·배포의 상태를 구분합니다.
- 결과물이 있으면 설명 위에 기준 경로를 먼저 표시하고 파일 링크로 연결합니다. 큰 결과는 비교·상태 표, 번호 목록, 폴더 트리 중 맞는 형식을 사용하며 짧은 답변에 강제하지 않습니다.
- 잘된 점은 확인된 성과, 잘못된 점은 문제·제약·미확인과 다음 조치로 간단히 기록합니다. 성과·문제를 억지로 만들거나 미검증을 ‘문제 없음’으로 보고하지 않습니다.
- 로컬 보고의 실제 경로와 원격 게시 문서의 공개 가능한 상대 경로·별칭을 구분합니다. 개인 경로·계정·자격증명·운영 자료는 원격 문서에 복사하지 않습니다.
- 주로 사용하는 work-rules의 작업 시작·완료 보고 절을 필요한 작업에 적용합니다. 그 skill이 설치/발견되지 않았다면 이 공통 지침만 적용하고 설치·발견을 완료했다고 주장하지 않습니다. 보고를 위해 다른 저장소를 준비하지 않습니다.
