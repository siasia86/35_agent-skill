# Codex Windows 준비 단계 검토

Windows 네이티브 PowerShell과 Python 3.14.8에서 기존 동봉 도구의 대표 사본을 새 TEMP fixture로 직접 실행했습니다. Windows 전체 skill 구현이나 개인 설치 완료 검토가 아닙니다.

## 1. 직접 실행 결과

| 검사                        | 결과                | 판정      |
|-----------------------------|---------------------|-----------|
| 기본 cp949 Markdown 11회    | 인코딩 오류 11회    | 실패      |
| 같은 입력의 UTF-8 실행 11회 | 기대 동작 11회      | 통과      |
| kiro-lock 기본 흐름 6회     | 기대 동작 6회       | 통과      |
| 대표 Python 4개 구문        | AST 파싱 오류 0개   | 통과      |
| Markdown 도구별 사본 7개    | 각 종류의 동일 해시 | 정적 확인 |

Markdown 입력은 정상·깨진 파일 링크·중첩 펜스 뒤 링크·미닫힘 펜스·깨진 앵커·중복 H1과 한국어 제목·본문·링크·푸터입니다. UTF-8 실행은 정상 0, 오류 1, 미닫힘 2의 종료 코드를 확인했습니다. 기본 실행에서 오류 입력의 종료 1은 인코딩 예외와 겹쳤습니다. 같은 종료 코드만으로 검사가 정상 수행됐다고 판정하지 않았습니다. helper는 획득·중복 획득 차단·소유 확인·다른 token 해제 차단·정상 해제·없는 lock 확인 차단을 검사했습니다. 잘못된 해제 뒤 bytes 보존과 정상 해제 뒤 lock·guard 부재를 확인했습니다.

## 2. 적용 한계

기본 환경은 UTF-8 mode 0, locale/출력 cp949였습니다. `-X utf8`는 mode 1과 UTF-8 출력을 적용했고 locale 자체는 cp949를 유지했습니다. 7개 동일 해시 사본은 대표 도구 실행과 bytes 대조의 근거입니다. 기존 19개 skill 전체의 Windows 모델 행동·환경 검증을 완료한 결과가 아닙니다. 실제 개인 설치·Codex 발견·자동 선택·동시 경쟁·ACL·Windows 전체 메타데이터·WSL·운영 적용은 미검증입니다. 기존 Linux 모델 사례를 Windows 최종본 사례로 사용하지 않습니다.

## 3. 기록과 다음 단계

실행 입력·stdout/stderr·원시 결과는 로컬 비공개 근거로 보존합니다. 공개 문서에는 판정에 필요한 비식별 결과만 기록하고 개인 경로·계정·raw 증거를 복사하지 않습니다.
