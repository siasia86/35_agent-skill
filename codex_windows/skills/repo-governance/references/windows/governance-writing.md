# 정책 문서 구조와 Windows 실행

## 문서 구조

정책 작성이 요청됐을 때 대상에 실제 적용된 구조와 템플릿을 사용합니다. 아래는 기존 기본 구조의 역할 안내이며 파일 탐색만으로 생성·이동을 시작하지 않습니다. 실제 대상의 지침이 다른 구조를 정하면 그 구조가 우선합니다.

```text
repository/
  .governance/
    GOVERNANCE.md     저장소 성격·적용 규칙·예외 요약
    ISSUE.md          이슈 원본
    TODO.md           미완료 작업·상태 원본
    PLAN.md           복합 작업 계획
    exceptions.md     필요한 경우 예외 상세
    verification.md   필요한 경우 저장소 검증 절차
```

신규 저장소가 이 기본 구조를 실제 채택했으면 GOVERNANCE·ISSUE·TODO·PLAN을 만들고 활성 항목이 없어도 상태를 기록합니다. 기존 저장소는 적용 지침에서 허용한 루트 문서를 migration 전까지 보존합니다. `verification.md`는 변경 유형별 검증이 여러 종류여서 분리가 필요한 경우 사용합니다. PLAN·TODO 작성이 필요한 경우 현재 제공된 planning-and-breakdown을 선택하되 정책 탐색 요청을 계획 생성 요청으로 확대하지 않습니다.

`governance_template.md`·`verification_template.md`가 실제 대상의 필수 입력으로 지정됐으면 확인하여 사용합니다. 접근 실패는 임의 대체하지 않습니다. 템플릿이 없고 필수도 아니라면 사용자 요구와 적용 지침으로 초안을 만들고 미결 조건을 남깁니다. 일반 작업에 중앙 저장소 clone을 요구하지 않습니다.

## 기술 범위

저장소 성격과 전역 기본값에서 달라지는 부분을 명확히 연결합니다. 유지하는 기준과 예외를 확인할 수 있게 쓰되 전역 규칙 전체를 중복 복사하거나 정책 우선순위를 바꾸지 않습니다.

| 작성 가능한 내용                     | 범위 밖 선언                         |
|--------------------------------------|--------------------------------------|
| 허용되는 개인 기본값의 저장소별 조정 | 시스템·관리 정책 무력화              |
| 저장소 전용 검증 절차                | 사용자 지시보다 우선한다는 선언      |
| 문서 역할·생명주기 예외              | 다른 저장소에 대한 규칙 강제         |
| 범위·조건·만료가 명확한 승인된 예외  | 영구 권한 확대·과거 승인 자동 재사용 |

정책 개정·배포가 요청되면 현재 중앙 관리 원본과 대상 배포 지침의 관계를 확인합니다. 파일 위치만으로 최신 중앙 원본이 실제 배포됐다고 주장하지 않습니다. 실제 개인 설정·raw 증거·계정·비공개 자료는 공개 정책 문서에 복사하지 않습니다.

## Windows 실행과 검증

Windows 네이티브 셸은 PowerShell입니다. 파일 작업은 확인한 절대 경로와 `-LiteralPath`·`Join-Path`를 사용합니다. PowerShell 5.1·7의 인코딩 차이를 확인하고 기존 BOM·개행을 의도 없이 바꾸지 않습니다. Python이 필요하면 실제 위치·버전을 확인한 Python 3.11 이상을 `python -X utf8 -B`로 사용하며 코드의 파일 입출력은 `encoding='utf-8'`을 명시합니다. WindowsApps 별칭은 런타임 설치 증거가 아닙니다.

네이티브 CLI의 종료 상태는 실제 도구 계약으로 판정합니다. PowerShell cmdlet 오류와 `$LASTEXITCODE`를 혼동하지 않습니다. `terraform plan -detailed-exitcode`의 변경 있음처럼 정상 차이를 나타내는 상태를 일반 실패로 처리하지 않습니다. 실행 예시가 현재 대상에서 실제 수행됐다고 보고하지 않습니다.

대상 지정 검사기·설정·버전을 우선합니다. 정해진 검사·정형 추출·확정된 기계적 수정은 지원되는 `gpt-6-luna / medium`에 묶음으로 배정하고 이미 배정된 worker는 재위임하지 않습니다. 미지원이면 이유를 남기고 담당자가 승인 범위에서 직접 수행할 수 있습니다. 검사는 도구·명령·범위·개수·종료 코드·진단·미실행을 구분하고 의미·정책·권한 판단은 담당자/root가 유지합니다.

필수 도구 부재·대상 0개·접근 실패·미실행을 통과로 처리하지 않습니다. 새 변경·실패·미결 근거가 없는 전체 반복 검사를 요구하지 않습니다. 정책 탐색·검증은 설치·ACL·키·운영 서비스 변경의 권한이 아닙니다.
