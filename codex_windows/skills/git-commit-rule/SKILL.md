# Git 커밋 메시지와 게시

현재 사용자 요청과 실제 저장소의 적용 지침을 먼저 확인합니다. 시스템·관리 정책과 실제 권한 안에서 사용자 명시 지시, 적용 저장소 지침, 개인 기본값 순으로 적용합니다. 메시지만 작성하거나 읽기 전용 검토하는 요청을 commit·push로 확대하지 않습니다.

## 메시지

`<type>: <한국어 설명>` 형식을 사용합니다. 접두사를 포함한 제목 전체를 50자 이내로 쓰고 끝에 마침표를 붙이지 않습니다. 여러 변경은 핵심 목적에 맞는 타입으로 설명합니다.

| 타입       | 용도                         |
|------------|------------------------------|
| `docs`     | 문서 추가·수정               |
| `fix`      | 버그·오타·깨진 링크 수정     |
| `feat`     | 새 기능·스크립트·자동화 추가 |
| `refactor` | 구조 변경·디렉터리 정리      |
| `chore`    | 설정·유지보수                |
| `style`    | 형식·표현 변경               |

```text
docs: Windows 사용 안내 추가
fix: README 문서 링크 수정
feat: 검증 결과 요약 기능 추가
refactor: 문서 참조 구조 정리
chore: 검사 설정 갱신
style: Markdown 표 정렬
```

## 검증과 게시

실제 Git 루트·브랜치·기존 변경·적용 AGENTS와 하위 지침을 확인하고 사용자 변경과 다른 작업을 보존합니다. 여러 세션에서는 작업 ID·담당 파일·예정 commit 파일을 명시합니다. 확인하지 않은 파일을 일괄 staging하지 않습니다.

일반 개인 개발의 기본 작업·게시 브랜치는 `main`입니다. 필요한 검증·기록 후 검토한 담당 파일만 commit·일반 push하고 원격 SHA와 commit 링크를 확인합니다. 이미 부여된 완료 절차의 승인을 반복 요청하지 않습니다. 병렬 작업·격리·장기 실험은 필요한 agent/task 브랜치·worktree를 사용하며 검증한 변경은 지정 통합 대상으로 반영합니다. 기존 브랜치를 자동 삭제하지 않습니다.

현재 사용자 제한, QA·Migration·복구 목적 브랜치, upstream 읽기 전용 경계와 원격 보호 규칙의 필수 PR·검사를 유지합니다. 브랜치 전환 전 기존 변경·미병합 commit·refs를 보존합니다. 읽기 전용·변경 0건은 commit·push하지 않습니다. 검사 실패·비밀값·다른 작업 변경은 게시하지 않으며 force push·release·운영 적용은 별도 범위입니다.

PowerShell 명령·staging·원격 확인이 필요하면 [Windows 게시 절차](references/windows/git-workflow.md)를 읽습니다. Markdown이 바뀌면 대상의 지정 검사기·설정을 우선하고 지정이 없을 때 실제 동봉 검사기를 사용합니다. 문서 역할·푸터·배지·날짜는 대상에 실제 적용된 지침을 따릅니다. 표현 기준이 필요할 때만 [STYLE](references/STYLE.md)을 읽습니다.

완료 보고는 실행·검증·미실행을 구분합니다. 로컬 commit·원격 게시·CI 완료를 각각 관찰한 범위로 보고하며 게시 실패는 원인과 미게시 상태를 남깁니다. 개인 경로·계정·자격증명·원형 설정·운영 자료를 공개 기록에 복사하지 않습니다.

이 폴더 전체가 사용 단위입니다. 형제 skill·중앙 설치기·다른 저장소를 필수 의존성으로 요구하지 않습니다. 설치·발견·선택·행동·게시 성공은 각각 별도 관찰입니다.
