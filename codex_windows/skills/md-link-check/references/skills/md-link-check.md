
# Markdown 링크와 헤딩 검사

실제 대상 파일·Git 루트·기존 변경과 적용 AGENTS·하위 지침을 확인합니다. 사용자 명시 지시와 실제 저장소 지침을 개인 기본값보다 우선하고 다른 작업을 보존합니다. 문서 역할·위치·푸터·배지·날짜·상태 처리는 대상에 실제 적용된 기준을 따릅니다. 중앙 작성·배포 원본의 미배포 변경을 자동 적용하지 않습니다.

## 도구 선택과 범위

저장소가 검사기·버전·설정을 지정했으면 이를 우선합니다. 지정이 없으면 폴더에 동봉한 `scripts/md-style-check.py`, `scripts/md-heading-check.py`, `scripts/md-link-check.py`와 공통 모듈 `scripts/md_common.py`를 사용합니다. Python 3.11 이상에서 `python -X utf8 -B`로 실행합니다. 중앙 설치기·전역 alias·형제 skill·다른 저장소·추가 패키지 설치는 필수 조건이 아닙니다.

| 검사                                    | 동봉 도구             | 별도 확인                         |
|-----------------------------------------|-----------------------|-----------------------------------|
| 내부 파일 링크의 파일 존재              | `md-link-check.py`    | reference-style 링크·네트워크 URL |
| 같은 파일 앵커·번호·레벨·참조 중복·목차 | `md-heading-check.py` | 다른 파일 앵커                    |
| 표 정렬·문체·푸터                       | `md-style-check.py`   | 대상 저장소 문서 정책             |

다른 파일 앵커는 대상 파일의 실제 헤딩과 등장 순서의 중복 suffix를 별도로 대조합니다. 링크 검사 통과를 외부 도달성이나 Markdown 전체 문법 통과로 확대하지 않습니다. 기본 제외·선택 TOML 설정의 실제 적용과 검사 파일 수를 기록합니다.

실행·오류·정형 수정에는 [Windows 검사 절차](../windows/markdown-checks.md)를, 앵커·목차·번호·펜스의 상세 규칙에는 [문서 구조 기준](../windows/markdown-structure.md)을 읽습니다. 문서 표현 기준이 필요한 경우에만 [STYLE](../STYLE.md)을 읽습니다.

## 배정과 완료 판정

검사 명령·정형 결과 추출·확정된 의미 불변 수정은 소유 담당자가 실제 지원을 확인한 `gpt-6-luna / medium`에 문서 묶음 단위로 배정합니다. 이미 배정받은 worker는 직접 수행하고 재위임하지 않습니다. 지원하지 않으면 이유를 기록하고 담당자가 승인 범위에서 직접 검사하며 기본 모델·config를 변경하지 않습니다.

배정에는 기존 작업 ID·실제 루트·담당 파일·입력 버전이나 해시·검사 명령과 설정·허용 수정·제외 범위를 적습니다. 반환에는 실제 모델·effort·도구 경로와 버전·명령·파일 수·각 종료 코드·진단·수정 diff·미검사를 담습니다. 의미·사실·상태·사용자 행동·승인·보류·헤딩 뜻·공유 파일 소유권 판단은 원 담당자나 root가 맡습니다.

소유 담당자는 핵심 진단·누락·diff를 대조하여 판정합니다. 대상 0개·필수 도구 부재·미실행은 통과가 아닙니다. 오류는 증거를 보존하고 원인을 교정하거나 root에 인계한 뒤 영향 범위만 재검증합니다. 새 근거 없는 전체 검사 반복과 검사기 수정으로 통과시키기를 하지 않습니다. 검사·정형 수정은 commit·push·설치 권한을 추가하지 않습니다.
