# 실행 가능한 계획과 작업 분해

현재 사용자 목표·대상·출력 위치·범위·핵심 제한을 확인하고 실제 Git 루트·기존 변경·적용 AGENTS와 하위 지침을 대조합니다. 시스템·관리 정책과 실제 권한 안에서 사용자 명시 지시, 적용 저장소 지침, 개인 기본값 순으로 적용합니다. 저장소가 없는 작업도 요청된 출력과 기존 자료를 보존합니다.

PLAN·TODO 생성·계획 내용 재작성에는 이 skill을 사용합니다. 실제 Plan 모드는 선택 사항이며 Default에서도 요청 범위의 조사·계획·문서 반영을 진행합니다. Plan 모드 미활성만으로 중단하거나 전환을 요구하지 않습니다. 실제 모드의 제한과 사용자 읽기 전용·계획만 요청 범위를 유지합니다. 기존 TODO의 상태·검증 근거·다음 행동만 갱신하는 일상 기록은 계획 재작성과 구분합니다.

## 계획 작성

현재 상태·기존 구조·의존성·위험·미지수를 필요한 범위에서 읽기 전용으로 조사합니다. 실제 제공된 파일·로그·Windows 서비스/프로세스·네이티브 CLI 자료를 사용하고 접근하지 못한 계정·규모·권한은 미결 사항으로 둡니다. 기술별 state·콘솔·도구는 해당 대상과 접근 범위가 주어진 경우에만 선택합니다.

정상 상태를 유지할 수 있는 기능 단위로 분해하고 의존성 순서로 배열합니다. 수직·위험·환경 분할을 상황에 맞게 조합합니다. 큰 태스크는 검증 가능한 더 작은 단위로 나누며 위험도 때문에 호환성 같은 선행 조건을 뒤로 밀지 않습니다. 체크포인트는 실제 위험과 의존성에 맞추고 고정 개수마다 문서·승인·agent를 자동 생성하지 않습니다.

PLAN은 목표·범위·담당·실행 순서·의존성·완료 기준·검증·복구·사용자 개입 조건을 연결합니다. TODO는 기존 ID·우선순위·담당·상태·선행 조건·다음 행동·완료 근거·PLAN 연결을 담습니다. 문서 역할·경로·양식·푸터·상태·게시 절차는 대상에 실제 적용된 지침을 따릅니다. 중앙 31의 작성·배포 원본이나 백업의 미배포 내용을 자동 적용하지 않습니다. 단순 작업에 새 문서·검증표·결과 폴더를 일괄 만들지 않습니다.

실행 플랫폼과 도구·대상·계정·설치·권한 의존성을 실제 조건으로 적습니다. Windows 로컬 실행은 PowerShell과 필요한 경우 Python 3.11 이상의 `python -X utf8 -B`를 사용합니다. 도구 설치·키·ACL·원격 권한 변경은 자동 실행하지 않고 요청 범위와 선행 조건을 구분합니다. 구체적인 분해·양식·완료 체크는 [계획 양식과 검증](references/windows/planning-templates.md)을 읽습니다.

## 계획과 연속 실행

계획만 요청됐으면 실행 가능한 명세와 미결 사항을 남깁니다. 계획 문서·검토 완료는 Goal 생성·구현·배포·게시의 새 승인이 아닙니다. Goal은 사용자가 명시적으로 요청한 경우에만 생성하고 일반 실행 요청에서 추론하지 않습니다. 이미 존재하는 Goal과 승인·보류를 보존합니다.

목표 실행이 요청되면 현재 선행 조건·보류를 확인하고 실행 가능한 항목 중 우선순위가 높은 작업부터 수행하며 같은 우선순위에서는 PLAN 순서를 따릅니다. 승인된 실행·빌드·자동 시험·로그 분석·호환성 검증을 agent가 수행하고 상태·근거를 갱신한 뒤 다음 준비된 작업으로 이어갑니다. 문서 완료·기능 완료·게시 완료를 각각 판정하고 대상 0개·미검사 범위를 완료로 확장하지 않습니다.

대기·보류에는 원인·필요 입력·재개 조건을 남기고 독립 작업을 계속합니다. 실패하면 영향받는 작업의 증거를 보존하고 원인 분석 후 새 근거에 따라 수정·영향 범위 재검증을 수행합니다. 같은 입력의 실패를 반복하거나 사용자에게 원인 분석 없는 반복 시험을 넘기지 않습니다. 변경·실패·미결 근거가 없으면 통과 검사를 반복하지 않습니다.

사용자 확인은 실제 권한 부족·명시 보류 해제·업무상 선택·자동 판정하기 어려운 사용성에 한정합니다. 먼저 자동화·도구·격리 환경으로 가능한 검증을 완료합니다. 담당 채팅·역할·작업 ID·이미 검증한 범위·준비한 실제 파일과 실행 방법·최소 확인 절차·회신 항목·재개 행동을 함께 안내합니다. 이미 승인된 범위를 다시 확인하지 않습니다. 자동 감시·별도 채팅·메시지·운영 권한 확대는 연속 실행의 기본값에 포함하지 않습니다.

## 역할과 최종 통합

단순 작업은 직접 처리하고 큰 계획에서 필요한 역할만 배정합니다. 사용자의 단일 창구인 root가 최종 배정·우선순위·검증·공통 파일 통합을 담당하며 소유 영역의 기능 원본과 상태는 해당 담당자가 유지합니다. 여러 저장소의 작업은 저장소 별칭과 기존 ID를 연결합니다. 같은 입력·범위·승인의 검토는 재사용합니다.

역할·모델 기준과 반환·오류 처리는 큰 작업에 필요할 때 [담당·모델·통합 기준](references/windows/planning-roles.md)을 읽습니다. 업무 역할은 추가 권한·직책별 필수 승인·자동 채팅/메시지·Goal·상시 감시를 만들지 않습니다. 모델·effort의 실제 지원과 선택을 확인하고 main/config를 자동 변경하지 않습니다.

## 검증과 마감

각 태스크의 완료 조건·검증·의존성·영향 범위·복구·미결 사항을 대조합니다. 계획 작성 태스크는 명세와 실행 가능성을 검증하며 실제 배포 성공으로 표시하지 않습니다. 기술별 검사 결과의 범위를 구분하고 미실행 항목을 기록합니다.

게시가 승인된 일반 개인 개발은 `main` 기본값과 실제 목적별 브랜치·사용자 제한·원격 보호 규칙에 따라 검토한 담당 파일만 commit·일반 push하고 원격 SHA를 대조합니다. 읽기 전용·계획만 요청된 범위는 유지합니다. 보고는 한국어로 결과·검증·미실행을 구분하고 개인 경로·계정·자격증명·원형 설정·운영 자료를 공개 기록에 복사하지 않습니다.

폴더 전체가 사용 단위이며 형제 skill·중앙 설치기·다른 저장소 설치를 필수 조건으로 요구하지 않습니다. 계획 실행에 필요한 점진적 변경·실패 복구의 최소 절차도 동봉 양식 참조에 포함되어 있습니다.
