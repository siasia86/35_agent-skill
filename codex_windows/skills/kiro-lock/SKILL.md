# 작업 잠금

## 잠금 계약

명칭은 유지하며 실행은 [lock.py](scripts/lock.py)를 사용합니다. 대상 프로젝트가 채택한 잠금 범위를 확인하고 실제 Git 루트 또는 worktree 루트에 적용합니다. 읽기 전용 파일·Git 조회는 잠금이 필요하지 않습니다. 잠금은 수정 권한을 추가하지 않습니다.

현재 작업에서 만든 비공개 세션 토큰을 유지합니다. 기존 잠금 파일의 토큰을 자기 토큰으로 채택하지 않습니다. 획득 실패·다른 소유·손상·노후 잠금·남은 guard는 자동 삭제하거나 덮어쓰지 않습니다. 시간 경과나 같은 사용자·호스트만으로 소유권을 인정하지 않습니다.

획득·소유 확인·완료/오류 정리의 실제 호출은 [잠금 실행](references/windows/locking.md)을 읽습니다. 완료와 오류 모두 같은 토큰으로 자기 잠금만 해제합니다. 10분 경과 또는 문맥 재개 뒤 쓰기 전 소유를 다시 확인합니다.

주 담당자가 범위·토큰·파일 담당을 직접 공유한 경우에만 하위 담당자가 같은 잠금으로 작업하고 최종 해제는 주 담당자가 수행합니다. hook 설치·활성화·개인 홈 변경은 포함하지 않습니다.

## 안전성 범위

도구는 독점 생성 guard로 협조자의 획득·확인·해제를 직렬화하고 독점 생성 lock으로 기존 파일을 보존합니다. 토큰·현재 사용자·호스트·파일 동일성을 확인하며 확인 가능한 symlink/reparse 경로를 거부합니다. 실패한 생성은 그 호출이 만든 파일이 여전히 동일할 때만 정리합니다.

Windows 파일 mode를 NTFS ACL 보호라고 주장하지 않습니다. 검사 사이의 비협조 경로 교체·hard-link·네트워크 파일시스템·ACL 경계를 완전히 차단하는 보안 장치가 아닙니다. 이런 환경은 검증된 저장소 잠금 또는 격리 작업본을 사용합니다. 수동 복구는 현재 소유·증거·사용자 요청을 확인하는 별도 조치입니다.
## 실행 기준

현재 사용자 요청·적용 저장소 지침·플랫폼 정책과 실제 권한을 따릅니다. 저장소 작업은 실제 Git 루트·기존 변경·하위 지침부터 확인하고 다른 작업과 비공개 자료를 보존합니다. 검토·명세 작성은 설치·운영 적용·게시 권한을 추가하지 않으며 이미 승인된 범위는 반복 확인하지 않습니다.

Windows PowerShell을 사용하고 파일 작업은 확인한 절대 경로와 `-LiteralPath`로 처리합니다. Python이 필요한 경우 실제 Python 3.11 이상을 확인해 `python -X utf8 -B`로 호출하고 UTF-8 입출력을 명시합니다. PowerShell 오류와 외부 명령의 `$LASTEXITCODE`를 각각 판정합니다. 업무에 필요한 선택 도구만 실제 설치·대상·권한을 확인하며 자동 설치하지 않습니다. Windows 네이티브에서 실행할 수 없는 기능은 범위 밖으로 표시합니다.

한국어로 결과와 실제 근거를 보고하고 통과·부분 검사·실패·미실행을 구분합니다. 폴더 안의 해당 참조만 필요할 때 읽으며 다른 저장소·형제 스킬 설치를 필수로 요구하지 않습니다.
