# 문서별 사실 검증

요청한 문서 각각의 내용 전체에서 사실 주장을 확인합니다. **추론 금지**를 적용하고, 확인한 근거에 맞춰 판정합니다. **기본은 확인된 오류를 최소 수정한 뒤 재검증**하는 방식입니다. 현재 사용자의 편집 제한과 적용 지침을 우선합니다.

## 1. 대상과 호출

`$fact-check`는 요청 문장 앞·중간·뒤에 올 수 있습니다. 따옴표로 감싼 스킬 이름도 요청 의도를 읽으며, 인접한 문서명·경로를 검증 대상으로 해석합니다. 이 예시는 터미널 명령이 아닙니다.

```text
PLAN TODO $fact-check
PLAN TODO "$fact-check" 수정 금지
$fact-check PLAN.md TODO.md 검토 후 확인된 오류만 수정
README.md의 §3 $fact-check
```

- `PLAN TODO $fact-check`는 PLAN과 TODO를 **각각 독립적으로**, 변경 부분에 한정하지 않고 문서 전체를 검증합니다. 전체 작업 상태 감사나 모든 저장소 문서 비교로 확대하지 않습니다.
- 경로를 지정하면 해당 파일을 사용합니다. `PLAN`, `TODO`처럼 역할명만 있으면 현재 작업 대상과 실제 적용 AGENTS·진입 문서가 지정한 현행 파일을 찾습니다. 이름이 비슷한 과거 사본·템플릿·다른 환경 문서를 함께 대상으로 삼지 않습니다.
- 대상이 생략되면 대화의 최근 작업 문서가 명확할 때만 사용합니다. 실제 대상이 복수로 해석되거나 없으면 필요한 경로를 확인하고, 대상 0개를 성공으로 보고하지 않습니다.
- 사용자가 지정한 절·주장·예외는 그대로 적용합니다. `검토만`, `수정 금지`이면 대상 파일·기록·설정을 변경하지 않습니다. 같은 요청 안에서 수정 지시가 충돌하면 편집 전에 모호한 범위를 확인합니다.

## 2. 주장과 근거

**추론 금지:** 근거에 없는 원인·의도·완료 상태·지원 범위·수치·선후 관계를 추론하거나 가정·일반화·외삽으로 채우지 않습니다. 확인 가능한 원문·직접 관찰·기록의 대조와 확인된 입력의 산술 검증만 사용합니다. 대조로 확정할 수 없으면 미확인 또는 판단 필요로 남기고 추론 결과를 사실이나 수정 근거로 사용하지 않습니다.

먼저 사실 주장과 예정 작업·요구사항·의견·예시·역사 기록을 구분합니다. 향후 목표나 체크리스트의 요구사항을 현재 구현 사실로 판정하지 않습니다. 실제 수행·검증 완료를 주장하는 항목은 해당 항목의 근거만 확인합니다.

한 줄에 예정과 현재 상태가 섞여 있으면 분리합니다. 예를 들어 `변경할 예정이며 아직 적용하지 않았다`의 예정은 사실 판정에서 제외하되, `아직 적용하지 않았다`는 현재 상태 주장으로 따로 근거를 확인합니다. 줄 전체를 예정으로 처리해 사실 주장을 빠뜨리지 않습니다.

체크박스 개수·완료율은 문서에 기록된 표시와 계산을 확인합니다. 표시만으로 실제 수행 성공을 추론하거나 모든 체크박스의 작업 상태 감사로 확대하지 않습니다. 별도로 수행·검증 성공을 단정한 문장이 있으면 그 주장에 한해 근거를 확인합니다.

검증할 사실에는 버전·날짜·수치·계산, RFC·포트·프로토콜·알고리즘, 명령·옵션·API 존재와 동작 조건, 기본값·지원 범위·필수 여부, 파일·설정·구현에 관한 단정이 포함됩니다. 원문에 없는 설계·작업·수치를 새로 제안하지 않습니다.

- 외부 기술 사실은 해당 버전·환경의 공식 문서·명세·공식 release·저장소 정의를 도구로 직접 확인합니다. `lynx`·`curl`·`grep` 또는 현재 환경에서 제공되는 브라우저·문서 조회·파일 읽기·`rg` 등 동등한 도구를 사용하며 특정 프로그램 설치를 필수로 요구하지 않습니다. 검색 요약이나 모델의 기억을 검증 근거로 쓰지 않습니다. 비공식 자료는 공식 근거를 찾는 단서로만 사용합니다.
- 로컬 사실은 그 주장에 필요한 실제 파일·설정·코드·Git·검증 기록을 읽어 확인합니다. 다른 작업이나 운영 자료를 일반 감사 대상으로 확대하지 않습니다. 정의가 존재하는 상태와 실제 실행 성공을 구분합니다.
- 문서가 연결한 `_reference`·관련 문서는 대조 자료로 사용하되 원출처·확인일·적용 버전을 확인합니다. 단순히 다른 문서도 같은 말을 한다는 이유로 사실을 확정하지 않습니다.
- 서로 다른 시점·환경·버전·분모를 먼저 구분합니다. 오래된 기록을 현재 값으로 덮어쓰거나 다른 범위의 수치를 모순으로 처리하지 않습니다.
- 근거 부재는 거짓이나 미실행의 증거가 아닙니다. 로그가 없으면 실행 여부를 미확인으로 남깁니다. 빌드 성공만으로 기능·UI·운영 검증 성공을 인정하지 않습니다.

사실 검증에 필요한 명령은 우선 정의·설정·도움말·기존 결과를 조회합니다. 설치·서비스 시작·운영 데이터 수정 등 부작용이 있는 행동은 이 스킬 호출만으로 수행하지 않고 현재 승인된 작업 범위를 확인합니다.

## 3. 금지 사항

- 검증 과정에서 대상 문서에 새로운 사실·문단·계획·예시·출처·근거 필요 표시를 추가하지 않습니다. 출처와 검증 설명은 결과 보고에 남깁니다.
- `더 정확하게`를 이유로 정상 문장을 늘리거나 표현을 꾸미지 않습니다. 오류로 확인되지 않은 문장의 윤문·보완도 수행하지 않습니다. 확인한 입력으로 오류를 찾는 산술 검증과 표현을 꾸미는 행위는 구분합니다.
- 도구로 확인한 출처 없이 수치를 다른 수치로 교체하지 않습니다.
- 검증 불가 항목을 추론·추측·가정으로 채우지 않습니다.
- AI 훈련 데이터·기억에 의존한 `~인 것으로 알고 있다` 식 검증을 하지 않습니다. 반드시 실제 도구로 원문·근거를 확인하고, 접근할 수 없으면 🟡 미확인으로 남깁니다.

## 4. 문서별 검증과 반복 상한

1. 실제 대상 파일과 요청 범위, 수정 허용 여부를 확정하고 문서 전체를 읽습니다.
2. **파일별로** 사실 주장을 추출합니다. 서로 다른 근거·판정이 필요한 주장은 분리하고, 같은 주장의 반복은 위치를 묶어 한 건으로 셉니다. 예정·의견·단순 체크박스 항목은 사실 검증 건수에 넣지 않습니다. 주장에 명시된 버전·환경·시점·조건을 함께 보존합니다.
3. 각 주장을 관련 근거와 대조하여 **✅ 확인됨 / ❌ 불일치 / 🟡 미확인·판단 필요**로 구분합니다. 불일치는 원문 주장과 반대 근거를, 🟡 항목은 확인을 막은 조건이나 해석·판정에 필요한 사항을 제시합니다. 근거 없이 ✅ 확인됨으로 처리하지 않습니다.
4. 문서 내부의 충돌이나 표현 모호함이 사실 판정에 영향을 주면 해당 줄과 가능한 해석을 보고합니다. 근거로 단일 해석을 확정할 수 없으면 임의로 고치지 않습니다.
5. 편집 제한이 없으면 확인된 오류만 고친 뒤 해당 주장과 변경 영향 범위를 재검증합니다. 변경은 diff로 표시하고 잔여 ❌ / 🟡 항목을 정리합니다.

한 번의 반복은 **사실 추출·공식/로컬 근거 대조 → 오류만 최소 수정 → 재검증 → 잔여 이슈 확인**입니다. 최초 반복을 포함해 **최대 2회** 수행합니다. 첫 재검증에서 새 근거로 확정된 오류가 남을 때만 한 번 더 수행하며, 같은 접근 실패나 미확인을 이유로 반복하지 않습니다. 두 번째 재검증 후 잔여 이슈를 보고하고 종료합니다. `수정 금지`이면 수정·수정 후 재검증 단계를 생략하고 판정·보고만 수행합니다.

문서 간 대조는 개별 주장의 근거 확인에 필요한 경우에 수행합니다. 사용자가 문서 간 정합성 검사도 명시한 경우에는 지정한 문서들의 같은 범위·시점에 관한 주장만 함께 대조하고, 개별 파일 결과와 교차 결과를 구분합니다.

## 5. 수정 조건

- `PLAN TODO $fact-check`처럼 편집 제한이 없는 호출은 확인된 오류를 수정합니다. `수정 금지`, `검토만`, `읽기 전용` 등 명시적 제한이 있으면 분석·보고만 하고 대상 파일·기록·설정을 쓰지 않습니다. 이 스킬의 기본 수정 규칙을 명시적 제한보다 우선하지 않습니다.
- 확인된 오류와 올바른 값·조건이 모두 근거로 확정될 때 기존 오류 구간만 최소 교체합니다. 출처·확인일·보충 설명은 보고에만 표시하며 대상 문서에는 덧붙이지 않습니다. 근거로 읽은 코드·설정·다른 문서는 별도 수정 요청 없이 편집하지 않습니다.
- 출처가 없거나 접근할 수 없는 내용은 자동 삭제하지 않습니다. 원래 내용을 그대로 보존하고 🟡 미확인으로 보고합니다.
- `기본`, `항상`, `모든 환경에서 지원` 같은 단정은 공식 근거로 오류와 올바른 표현이 모두 확인될 때만 최소 교체합니다. 조건을 임의로 추가하거나 뒷받침할 근거 없이 다른 단정으로 교체하지 않습니다.
- 날짜가 최신이거나 문서 제목이 PLAN·TODO라는 이유만으로 기준 문서를 선택하지 않습니다. 실제 적용 지침과 사용자가 지정한 기준을 따릅니다. 판정 기준이 서로 충돌하면 판단 필요로 남깁니다.
- 다른 작업의 편집을 보존하고 수정 직전에 대상 변경을 다시 확인합니다. 사실 검증을 이유로 작업 순서·문서 역할·설정·배포 정책을 재설계하지 않습니다.

## 6. 결과 보고

한국어로 **문서별** `=== Fact Check: {filename} ===` 아래에 항목마다 ✅ / ❌ / 🟡 판정을 표시합니다. 원문 위치와 검증한 주장을 식별할 수 있게 남깁니다. **❌ 항목은 실제 확인한 출처(URL, RFC 번호, `_reference` 파일 경로 또는 로컬 근거 파일·줄번호)를 반드시 병기**합니다. ✅ 항목은 보고에서 출처를 생략할 수 있지만 도구로 근거를 확인하는 의무는 동일합니다. 🟡 항목은 검증 불가 이유나 판정에 필요한 사항을 밝힙니다.

수정했다면 **모든 수정 항목에 대해 수정 전 ❌ 판정과 출처, 수정 후 ✅ 판정 또는 잔여 판정**을 빠짐없이 표시합니다. 오류 부분은 `diff` 코드블록의 삭제·추가 줄로 표시하며 단순 화살표 설명으로 대체하지 않습니다. 주장 단위를 유지하여 수정 전·후를 중복 집계하지 않습니다. 최종 요약은 파일별 **검증 항목 수·정확 수·수정 수·잔여 ❌ / 🟡 항목의 수와 내용·수행 반복 수**를 포함합니다. 정확 수는 마지막 검증에서 ✅ 확인됨인 항목 수이며, 오류가 수정되어 확인된 항목도 한 번만 셉니다. 검증 수가 정확 수와 잔여 판정 수의 합과 일치하는지 확인합니다. 일부 주장·절만 검사했다면 제외·미완료 범위를 밝히며 전체 통과로 보고하지 않습니다. 형식·링크·외부 도달성 검사와 내용 사실 검증도 구분합니다.

출력 직전에 각 ❌ 항목의 근거 출처가 실제 URL·RFC 번호·파일 경로로 명시되었는지, 모든 수정의 diff와 문서별 집계가 있는지 확인합니다. `체크박스 4개 중 2개` 같은 설명만으로 출처 경로를 대체하지 않습니다. 같은 대상 문서의 표시·계산이 근거라면 그 문서의 실제 경로와 근거 줄을 출처로 병기합니다.

결과 예시는 다음과 같습니다.

```text
=== Fact Check: PLAN.md ===
✅ 7행 지원 언어 3개 — _reference/languages.json 확인
❌ 6행 현재 포트 7300 — _reference/config.json의 Port는 7302
🟡 9행 기능 검증 완료 — _reference/ui-result.log에 접근할 수 없음
수정: 없음 — 수정 금지 요청
요약: 검증 3 / 정확 1 / 수정 0 / 잔여 ❌ 1·🟡 1 / 반복 1회
잔여: 현재 포트 불일치, 기능 검증 기록 미확인
```

기본 수정 모드의 오류 부분 diff 예시는 다음과 같습니다.

```diff
-현재 개발 서버 포트는 7300이다.
+현재 개발 서버 포트는 7302이다.
```
