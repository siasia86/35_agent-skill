
# 저장소 지침 탐색과 적용

저장소별 규칙은 실제 대상에 적용된 AGENTS·하위 지침·`.governance/`에서 선택하여 읽습니다. 경로·저장소 이름·과거 도입 표를 현재 정책·설치 상태·소유권·권한의 근거로 사용하지 않습니다. 실제 Git 루트·현재 브랜치·기존 변경을 확인하고 다른 작업과 비공개 자료를 보존합니다. worktree의 `.git` 파일도 유효합니다.

## 탐색

```powershell
# $TargetPath는 현재 요청의 실제 대상 디렉터리입니다.
$GitRoot = git -C $TargetPath rev-parse --show-toplevel
if ($LASTEXITCODE -ne 0) { throw 'Git 루트 확인 실패' }
git -C $GitRoot status --short
if ($LASTEXITCODE -ne 0) { throw '기존 변경 확인 실패' }
$GovernanceDir = Join-Path $GitRoot '.governance'
if (Test-Path -LiteralPath $GovernanceDir -PathType Container) {
    Get-ChildItem -LiteralPath $GovernanceDir -Force
}
```

적용 AGENTS·AGENTS.override·대상 하위 지침을 각 범위에 맞춰 확인합니다. `.governance/INDEX.md` 등 진입 문서가 지정됐다면 그 문서부터 관련 항목만 읽습니다. 실제 `GOVERNANCE.md`, `exceptions.md`, `verification.md`는 현재 작업에 필요한 부분을 선택합니다. 선행 점 이름·숨김 속성 때문에 존재를 추정하지 않습니다.

`.governance`가 없으면 실제 적용 AGENTS와 개인 기본값을 사용하며 새 정책 파일 생성을 선행 조건으로 요구하지 않습니다. 필수로 지정된 지침의 접근 실패는 규칙 부재가 아니므로 영향받는 판단을 보류하고 원인을 확인합니다. 다른 저장소나 중앙 profile을 임의 대체 규칙으로 사용하지 않습니다.

## 우선순위와 범위

시스템·개발자·관리 정책과 실제 권한 안에서 사용자 명시 지시, 적용 저장소 지침, 개인 skill 기본값 순으로 적용합니다. 변경되지 않은 사용자 범위·승인·명시 보류는 유지하며 세션 종료만으로 승인이나 보류가 사라졌다고 단정하지 않습니다. 충돌은 적용 출처와 영향 구간을 밝히고 현재 지시로 해결합니다. 사용자 지침도 상위 정책·실제 권한을 변경하지 않습니다.

저장소 지침은 해당 저장소의 역할·예외·문서 생명주기·검증·게시 범위를 정합니다. 다른 저장소의 정책을 강제하거나 사용자보다 우선한다고 선언하지 않습니다. 중앙 31의 `codex/template`·`codex/profile`은 작성·배포 원본이며 대상이 실제 채택한 범위만 적용합니다. 미배포 변경·백업·과거 승인을 자동 적용하지 않고 중앙 조회는 출처 확인·개정·배포에 필요할 때만 수행합니다.

이미 승인된 작업은 자율 진행하고 같은 승인을 반복 요구하지 않습니다. 파괴 작업·이력 재작성·자격증명 취급·ACL 변경·공유 시스템·운영 적용·범위 밖 게시 등은 실제 다음 동작이 현재 승인 범위에 포함되는지 확인합니다. 정책 탐색과 경로 존재는 새 권한이 아닙니다. 저장소의 예외로 플랫폼·원격 보호 규칙·현재 권한을 우회하지 않습니다.

## 정책 문서 작성

정책 신규 작성·초기화·개정은 사용자 요청 범위에서만 수행합니다. 기존 루트 문서를 자동 이동·덮어쓰기하지 않습니다. 실제 채택된 템플릿과 문서 역할·위치·상태·게시 기준을 확인합니다. 상세 작성 범위는 필요한 경우 [정책 구조와 Windows 실행](../windows/governance-writing.md)을 읽습니다.

기본 작업·게시 브랜치는 일반 개인 개발에서 `main`입니다. 현재 사용자 제한과 목적별 브랜치·upstream 읽기 전용 경계·필수 PR·검사를 우선하며 검증 후 검토한 담당 파일만 commit·일반 push합니다. 읽기 전용·변경 0건은 게시하지 않고 force push·release·운영 적용은 별도 범위로 유지합니다.

한국어로 실행 목적·관찰·다음 행동을 간결하게 보고하고 실행·검증·미실행을 구분합니다. 정책 작성·설치·새 세션 발견·실제 행동·원격 적용·Git 게시를 각각 관찰한 범위로 보고합니다. 폴더 전체로 단독 사용할 수 있으며 중앙 설치기·형제 skill·별도 정책 저장소를 기본 실행의 필수 의존성으로 요구하지 않습니다.
