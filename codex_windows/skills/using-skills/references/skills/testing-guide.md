
# 테스트 설계

## 시험 선택

사용자 요청과 변경 위험에 맞춰 저장소의 실제 runner를 우선합니다. 없는 pytest·scanner를 설치됐다고 가정하지 않고 표준 `unittest` 등 가능한 수단을 사용하거나 미실행을 보고합니다. 가역적인 낮은 영향 변경과 구현을 그대로 복제하는 시험을 불필요하게 추가하지 않습니다.

| 대상          | 시험                                         |
|---------------|----------------------------------------------|
| 함수·클래스   | 순수 로직 단위 시험, 경계·동등 분할          |
| 모듈·API 연결 | 통합과 계약·상태 코드                        |
| 결함 수정     | 실패 재현 후 회귀 검사                       |
| 인프라 변경   | 문법·영향 계획·실제 적용 뒤 상태·건강·정합성 |

## 설계 원칙

Arrange → Act → Assert로 준비·실행·판정을 분리합니다. 시험 간 의존을 없애고 반복 가능한 fixture와 자동 판정을 사용합니다. 단위 시험은 외부 I/O를 피하되 통합 시험의 실제 I/O까지 금지하지 않습니다.

범위에는 min-1, min, min+1, max-1, max, max+1 중 의미 있는 값을 고릅니다. 유효·무효 동등 그룹별 대표와 None·빈 문자열·빈 목록을 실제 계약에 맞춰 포함합니다. 정상·오류·예외·분기 경로와 적용 가능한 멱등성·부분 실패를 확인합니다.

5축으로 놓친 조건을 찾습니다: 입력(빈값·길이·Unicode), 환경(디스크·메모리·네트워크), 상태(초기·부분 쓰기·재시작), 시간(동시성·timeout·순서), 자원(핸들·pool·한도). 해당 축마다 의미 있는 조건을 선택하고 비적용을 억지로 만들지 않습니다.

pytest가 실제 있는 경우 `test_<module>.py`, `test_<target>_<condition>_<expected>()`, parametrize·fixture·raises를 활용합니다. 외부 API·DB 등 의존 대역은 필요한 경계에 한정합니다. 실제 파일 저장·잠금 보장을 시험할 때 파일시스템 전체를 mock해 그 보장을 지우지 않습니다.

상세 도출·실패 주입·파일 경합·파서 회귀는 [경계·실패 조건 시험](../resources/edge_case_testing.md)을 필요할 때 읽습니다.

## Windows 검증

Python은 `python -X utf8 -B -m unittest discover` 또는 실제 제공된 runner로 실행합니다. PowerShell parser·Python AST 검사는 실제 프로그램 실행과 구분합니다. 파일 공유·읽기 전용·공백/한글 경로·CRLF·인코딩·부분 저장·리소스 정리 등 지원 계약에 맞는 fixture를 사용합니다.

선택 인프라 도구의 `validate`·형식 검사·plan은 실제 설치·대상·권한이 확인된 업무에만 적용합니다. 도구가 있다고 daemon·인증·backend가 준비됐다고 가정하지 않습니다. Docker 건강은 실제 컨테이너와 HEALTHCHECK가 있을 때만 판정합니다. Windows 네이티브에서 지원되지 않는 실행 기능은 범위 밖입니다.

검사 실패는 영향받는 변경을 멈추고 증거 보존·원인 조사·수정 뒤 재검사합니다. 시험 목적·대상·runner·종료 상태·검사 수·제외·미실행을 보고하며 단일 정상 경로만으로 전체 동작을 보장하지 않습니다.
## 실행 기준

현재 사용자 요청·적용 저장소 지침·플랫폼 정책과 실제 권한을 따릅니다. 저장소 작업은 실제 Git 루트·기존 변경·하위 지침부터 확인하고 다른 작업과 비공개 자료를 보존합니다. 검토·명세 작성은 설치·운영 적용·게시 권한을 추가하지 않으며 이미 승인된 범위는 반복 확인하지 않습니다.

Windows PowerShell을 사용하고 파일 작업은 확인한 절대 경로와 `-LiteralPath`로 처리합니다. Python이 필요한 경우 실제 Python 3.11 이상을 확인해 `python -X utf8 -B`로 호출하고 UTF-8 입출력을 명시합니다. PowerShell 오류와 외부 명령의 `$LASTEXITCODE`를 각각 판정합니다. 업무에 필요한 선택 도구만 실제 설치·대상·권한을 확인하며 자동 설치하지 않습니다. Windows 네이티브에서 실행할 수 없는 기능은 범위 밖으로 표시합니다.

한국어로 결과와 실제 근거를 보고하고 통과·부분 검사·실패·미실행을 구분합니다. 폴더 안의 해당 참조만 필요할 때 읽으며 다른 저장소·형제 스킬 설치를 필수로 요구하지 않습니다.
