
# 상황보고

## 1. 범위와 근거

- 정식 호출은 `$status-report`입니다. 일반적인 상황보고 요청에도 선택하며, 단순 사실 질문과 일반 작업 진행·완료 보고는 별도 상황조사로 바꾸지 않습니다.
- 요청한 범위만 읽기 전용으로 대조합니다. 범위가 없으면 현재 채팅의 작업을 대상으로 하며, 그 채팅의 별도 승인 작업도 함께 요약합니다. 다른 담당은 입력에 등장하더라도 요청한 대상에만 포함합니다. 복수 담당은 지정된 대상만 확인하고 전체 담당을 자동 조회하지 않습니다.
- 현재 범위의 최신 소유 원본·직접 근거만 필요한 부분을 읽습니다. 이미 문맥에 있는 유효한 근거는 재사용하고 확인 시점·대상·한계를 밝힙니다. 요청이 지정한 과거 시점은 출력에서 밝히고 최신 직접 검증으로 바꾸지 않습니다. 형제 skill 본문·공통 지침 전체·다른 저장소를 필수로 읽지 않습니다.
- 직접 검증한 결과, 담당자가 보고한 결과, 미확인을 구분합니다. 부분 완료·설치·발견·선택·실제 행동·게시를 각각 관찰한 범위로 보고하고, 오래된 기록이나 담당자 주장을 현재 직접 검증으로 바꾸지 않습니다. 다른 agent의 로그 열람이나 입력에만 서술된 열람 사실을 현재 응답자의 직접 검증으로 바꾸지 않습니다.

## 2. 출력 계약

- 한국어로 현재 결론과 유효한 미해결 사용자 개입을 먼저 짧게 요약한 뒤 표와 상세 근거 링크를 제공합니다. 사용자 개입이 없으면 없다고 밝힙니다.
- 상황보고 요청에는 **대상·담당 / 확인된 결과 / 남은 조건 / 사용자 확인용 `.md`**의 4열 표를 실제 응답에 작성합니다. 대상·담당에는 실제 담당과 필요한 저장소 별칭·기존 ID를 연결하고, 결과와 미실행·미확인·선행·보류·재개 조건을 구분합니다.
- 첫 열 셀은 대표 상태 이모지·공백 1칸·한국어 상태 텍스트로 시작합니다. ✅ 검증 완료, 🟢 진행 중, 🟡 확인 대기·미확인, ❌ 검사 실패, 🔴 작업 중단, 🟠 검토·조율, 🔵 참고, 🟣 예정 중 근거에 맞는 상태를 표시합니다. 별도 상태 열·빈 열을 만들거나 같은 대표 상태를 다른 열에 반복하지 않습니다.
- 마지막 열은 사용자가 실제 확인·시험·입력·선택할 준비된 안내 `.md`만 연결합니다. 안내 링크 제목은 그 문서에 있는 실제 사용자 행동 범위를 유지합니다. PLAN·TODO 위치나 단순 결과·참고 문서로 대신하지 않습니다. 결과 문서에 실제 안내가 있으면 해당 안내 구간으로 연결할 수 있습니다.
- 실제 사용자 행동 제목과 안내 링크 제목 앞에는 🟡 확인·시험·입력 또는 🟠 선택·판단을 표시합니다. 이 표시는 첫 열의 대표 상태와 목적이 다르므로 유지합니다. 사용자 행동이 없으면 `사용자 확인 없음`, 안내가 아직 없으면 `안내 준비 중`과 필요한 입력·재개 조건을 밝힙니다. 존재하지 않는 링크나 표를 채우기 위한 문서를 만들지 않습니다.
- 이미 해결한 사용자 요청은 제외하고 현재 유효한 개입만 안내합니다. 표는 소유 상태를 요약하며 별도 기능 상태 원본이나 완료 판정을 만들지 않습니다.

## 3. 실행 경계

보고 요청 자체로 파일 수정·검사 재실행·Goal 생성이나 변경·게시·다른 채팅 메시지를 시작하지 않습니다. 기존 승인 작업과 사용자 보류는 유지합니다. 이 보고의 읽기 전용 범위를 별도로 승인된 작업 전체에 전파하지 않습니다.
