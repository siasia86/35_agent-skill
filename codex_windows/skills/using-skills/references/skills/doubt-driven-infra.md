
# 결정 교차 검증

## 적용과 절차

운영 환경, 권한·접근 규칙, 네트워크 구조, 데이터베이스 업그레이드, 삭제·마이그레이션, 익숙하지 않은 인프라 코드 등 비자명한 결정에 적용합니다. 단순 태그·설명·형식 변경과 명확한 최소 변경에 일괄 적용하지 않습니다. 완성 코드 리뷰와 별개로 진행 중 결정의 가정을 검증합니다.

1. **주장:** 변경, 안전하다고 보는 이유, 영향받는 서비스·사용자, 복구 방법을 명시합니다.
2. **분리:** 코드·plan·계약·필요한 원시 근거만 검토 입력으로 분리합니다. 자신의 정답·추론을 입력에 섞어 검토를 유도하지 않습니다.
3. **반박:** 범위 초과, 의존성, 실행 순서, rollback 영향, state와 실제 리소스 차이, 암묵적 가정이 깨지는 조건을 찾습니다.
4. **조정:** 실제 위험은 영향 작업을 멈추고 수정합니다. 검증 필요는 해당 증거를 확인합니다. 사소한 우려는 이유와 함께 기록합니다.
5. **종료:** 실제 위험 해소와 검증 필요 항목 확인 뒤 종료합니다. 같은 입력의 통과 검토를 반복하지 않습니다. 3회 사이클 안에 해결하지 못하면 미결 판단과 필요한 사용자 결정을 전달합니다.

독립 검토는 실제 사용 가능한 협업 도구와 승인 범위에서 수행하고 입력·범위·결과를 기록합니다. 도구가 없거나 범위 밖이면 자기 검토와 구분해 독립 검토 미실행을 보고합니다. 기존 승인을 유지하되 승인만으로 미검증을 통과 처리하지 않습니다.

## 검증의 한계

실제 업무에 채택한 Windows CLI의 대상·계정·리전·backend를 확인한 뒤 승인된 조회만 실행합니다. Terraform `plan -detailed-exitcode`는 0 변경 없음, 2 변경 있음, 1 오류입니다. 변경 있음은 오류도 적용 승인도 아닙니다. plan과 IAM 시뮬레이션은 서비스의 모든 보안·의존성 동작을 보장하지 않습니다.

개발 환경 성공을 운영 환경으로 확장하지 않고 네트워크·권한·데이터 차이를 검증합니다. 결과에 안전성 주장별 근거, 해소한 위험, 미확인 조건, 실제 독립 검토 여부를 남깁니다. 검토 완료로 apply·권한 변경·게시를 시작하지 않습니다.
## 실행 기준

현재 사용자 요청·적용 저장소 지침·플랫폼 정책과 실제 권한을 따릅니다. 저장소 작업은 실제 Git 루트·기존 변경·하위 지침부터 확인하고 다른 작업과 비공개 자료를 보존합니다. 검토·명세 작성은 설치·운영 적용·게시 권한을 추가하지 않으며 이미 승인된 범위는 반복 확인하지 않습니다.

Windows PowerShell을 사용하고 파일 작업은 확인한 절대 경로와 `-LiteralPath`로 처리합니다. Python이 필요한 경우 실제 Python 3.11 이상을 확인해 `python -X utf8 -B`로 호출하고 UTF-8 입출력을 명시합니다. PowerShell 오류와 외부 명령의 `$LASTEXITCODE`를 각각 판정합니다. 업무에 필요한 선택 도구만 실제 설치·대상·권한을 확인하며 자동 설치하지 않습니다. Windows 네이티브에서 실행할 수 없는 기능은 범위 밖으로 표시합니다.

한국어로 결과와 실제 근거를 보고하고 통과·부분 검사·실패·미실행을 구분합니다. 폴더 안의 해당 참조만 필요할 때 읽으며 다른 저장소·형제 스킬 설치를 필수로 요구하지 않습니다.
