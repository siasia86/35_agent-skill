
# 배포 점검

## 준비 점검

준비 완료는 배포 승인과 구분합니다. 실제 배포 기술·대상·사용자 요청에 해당하는 항목을 선택하고 비적용 이유를 남깁니다. 코드 리뷰 요청에는 실제 운영 적용을 포함하지 않습니다.

| 영역 | 확인할 근거                                                   |
|------|---------------------------------------------------------------|
| 변경 | 요구·검토 결과, 문법·시험, 예상 리소스와 삭제·교체 영향       |
| 보안 | 실제 최소 권한·비밀 노출·암호화·접근 규칙                     |
| 복구 | 변경 전 상태, 실제 백업·호환성, 소요 시간·중단 조건·복원 검사 |
| 관찰 | 배포 전 정상 지표, 로그·건강 검사·알림의 실제 준비            |
| 실행 | 대상·계정·권한·버전, 필요시 유지보수 시간·승인된 공지         |
| 사후 | 실제 서비스·리소스·정합성·지표·알림 회복, 코드·시간·담당 기록 |

공개 HTTPS에 필요한 공개 inbound와 관리 포트·내부 backend의 불필요한 공개를 구분합니다. 모든 `0.0.0.0/0`를 일괄 실패 처리하지 않고 용도·포트·대상·최소 권한을 평가합니다. 공지·알림은 사용자 요청 또는 적용 절차로 승인된 경우만 전송합니다.

## 단계별 배포

의존성과 앱·데이터 호환성을 먼저 준비하고 작은 논리 변경 또는 canary → 일부 → 전체 순서로 검증합니다. 비율·관찰 시간·지표 한도는 실제 서비스에 맞춰 정하며 고정 30분/1시간 대기를 강제하지 않습니다. 단계마다 건강·중단·복구 조건을 확인한 뒤 다음 단계로 갑니다.

실패하면 영향 작업을 멈추고 로그·상태를 보존해 원인을 좁힙니다. 시간만으로 일괄 rollback하지 않고 데이터 손실·구버전 호환성·검증된 복귀·복원 수단과 전진 수정 조건을 비교합니다. 마이그레이션 포함만으로 rollback 불가라고 판단하지 않습니다.

state 백업은 실제 backend를 사용하는 경우에만 비공개로 보존합니다. PowerShell 기본 리다이렉션 인코딩으로 bytes를 바꾸지 않습니다. state 백업을 리소스·데이터 rollback과 혼동하지 않습니다.

## 완료 판단

실제 업무의 코드 리뷰, 각 단계 검증, 서비스 건강, 정합성, 모니터링 안정, 복구 가능성에 근거가 있어야 완료로 표시합니다. 무알림만으로 정상이라고 판단하지 않습니다. 도구·검사가 없거나 실행하지 않았다면 이유와 영향을 남깁니다. commit·게시·설치·운영 적용·검증 결과를 각각 보고합니다.
## 실행 기준

현재 사용자 요청·적용 저장소 지침·플랫폼 정책과 실제 권한을 따릅니다. 저장소 작업은 실제 Git 루트·기존 변경·하위 지침부터 확인하고 다른 작업과 비공개 자료를 보존합니다. 검토·명세 작성은 설치·운영 적용·게시 권한을 추가하지 않으며 이미 승인된 범위는 반복 확인하지 않습니다.

Windows PowerShell을 사용하고 파일 작업은 확인한 절대 경로와 `-LiteralPath`로 처리합니다. Python이 필요한 경우 실제 Python 3.11 이상을 확인해 `python -X utf8 -B`로 호출하고 UTF-8 입출력을 명시합니다. PowerShell 오류와 외부 명령의 `$LASTEXITCODE`를 각각 판정합니다. 업무에 필요한 선택 도구만 실제 설치·대상·권한을 확인하며 자동 설치하지 않습니다. Windows 네이티브에서 실행할 수 없는 기능은 범위 밖으로 표시합니다.

한국어로 결과와 실제 근거를 보고하고 통과·부분 검사·실패·미실행을 구분합니다. 폴더 안의 해당 참조만 필요할 때 읽으며 다른 저장소·형제 스킬 설치를 필수로 요구하지 않습니다.
