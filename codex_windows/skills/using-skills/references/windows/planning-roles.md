# 큰 계획의 담당·모델·통합

단순 작업은 직접 처리하고 큰 계획에서 실제 필요한 역할만 배정합니다. 사용자가 정한 역할·범위 문서가 있으면 그 문서를 참조하며 특정 저장소의 경로를 공통 필수 규칙으로 강제하지 않습니다. 역할은 권한을 추가하지 않습니다.

## 역할

- root는 사용자의 단일 창구로 최종 배정·우선순위·검증·공통 파일 통합을 담당합니다. 소유 영역의 실제 기능 상태와 원본은 담당자가 유지하고 root가 기존 ID·근거·보류를 연결합니다.
- planner는 요구·우선순위·완료 기준 관점과 기술·의존성·검증·복구 관점을 묶어 초안을 작성합니다. 실행 담당·대상 작업본·브랜치·입력 버전/해시·담당/제외 파일·반환 근거를 연결하여 root가 최종 배정하도록 합니다.
- CPO·CTO는 위 요구·기술 관점을 뜻합니다. 필요할 때 COO 관점으로 배정·진행 정리를 지원하고 CISO 관점으로 보안 영향·조건·근거를 검토합니다. 직책마다 별도 agent·필수 승인 관문을 만들지 않습니다.

같은 입력·범위·승인의 검토는 재사용합니다. 소유 담당자는 단일 파일의 기능 원본을 관리하고 공유 파일은 root가 검증 후 통합합니다. 단순 조회를 큰 병렬 계획으로 확대하지 않습니다.

## 모델 기준

| 작업                                                 | 운영 기준             |
|------------------------------------------------------|-----------------------|
| 명확한 지정 자료·규칙의 정형 추출                    | Luna                  |
| 정해진 검사·명확한 단순 스크립트·확정된 기계적 수정  | `gpt-6-luna / medium` |
| 검색·비교·선별·출처 확인                             | Sol 6.1 medium        |
| 복수 조건 이미지 판정·여러 저장소 계획과 의존성 분석 | Sol 6.1 high          |
| 중요한 최종 설계 판단                                | Astra                 |

실제 도구의 모델·effort 지원과 선택을 확인하고 main/config를 자동 변경하지 않습니다. 미지원이면 한계를 알리고 root 또는 소유 담당자가 이어받습니다. 직접 대체 수행을 지정 모델의 수행으로 보고하지 않습니다. 이 기준은 역할 배정이며 성능 실측 주장이 아닙니다.

정해진 검사·정형 추출·합의된 기계적 수정은 총괄을 포함해 문서나 작업 묶음 단위로 Luna에 기본 배정합니다. 배정받은 worker는 직접 수행하고 재위임하지 않습니다. 작은 잔여 작업을 여러 agent로 쪼개지 않습니다. 의미·사실·설계·상태·권한 판단은 기존 담당자가 유지합니다.

## 배정과 반환

배정에는 기존 작업 ID·실제 저장소 루트·대상 작업본과 브랜치·입력 버전/해시·담당/제외 파일·명령과 설정·허용 수정·완료 기준·반환 근거를 적습니다. 검사·정형 수정은 기존 승인·권한 범위를 넓히지 않고 게시 권한은 원 담당자/통합 담당자에게 유지합니다.

반환에는 출처·범위·실제 개수·누락·미확인과 실제 모델·effort·도구·명령·종료 코드·진단·수정 diff를 남깁니다. 담당자는 핵심 진단·누락·diff를 대조하여 완료를 판정합니다. 입력·도구·판단 오류를 구분하고 오류 결과 사용을 보류하여 증거를 보존한 뒤 교정·적합 모델/root 인계·영향 범위 재검증으로 처리합니다. 같은 실패와 전체 검사를 무조건 반복하지 않습니다.

모델 선택·업무 역할·계획 작성은 추가 권한·자동 채팅/메시지·Goal·상시 감시를 만들지 않습니다. 사용자 명시 요청 없이 별도 채팅 생성이나 메시지 전송을 하지 않습니다. 계획만 요청됐으면 초안과 미결 사항을 반환하고 구현·게시를 시작하지 않습니다.
