# 작업 현황판 갱신

기존 소유 PLAN·TODO·검증 기록을 근거로 담당의 현재 작업을 짧게 공유합니다. 현황판 요약은 기능 상태 원본을 대신하지 않습니다.

## 1. 대상과 갱신 담당 확인

- 최신 사용자 지시, 실제 적용 AGENTS·배정 문서에서 현황판 위치와 자기 카드·통합 담당을 확인합니다. 현황판이 다른 저장소에 있으면 그 저장소의 지침도 해당 쓰기 범위에 적용합니다. 특정 프로젝트·드라이브·담당 수를 개인 skill에 고정하지 않습니다.
- 대상 현황판의 사용법·카드 형식·기존 작업 ID를 읽습니다. 이름이 비슷한 파일만 보고 담당을 추정하지 않습니다. 사용자 지정 경로가 없으면 현재 프로젝트의 지침이 연결한 현황판을 찾습니다.
- 현황판이나 자기 카드가 아직 배정되지 않았다면 현재 작업을 계속하면서 배정 조건을 반환합니다. 새 프로젝트라는 이유로 공유 현황판·카드·기능 TODO를 임의로 생성하지 않습니다. 단기 worker의 결과는 기존 소유 담당 카드로 인계합니다.
- 담당은 자기 카드만 갱신하고, 지정 통합 담당은 공통 현황판을 집계합니다. 기존 지시에 포함된 갱신은 반복 승인을 요청하지 않습니다. skill 선택만으로 다른 담당 파일·공통 파일의 쓰기 권한을 얻지 않습니다.

## 2. 근거에 따른 담당 카드 갱신

작업 시작, 의미 있는 결과·검증 변화, 대기·실패·중단, 완료·인계 때 갱신합니다. 같은 내용의 반복 기록이나 명령마다 갱신은 생략합니다.

- 자기 카드와 관련 소유 원본의 변경된 구간만 대조합니다. 같은 입력의 기존 검토·통과 검사를 재사용하고 전체 채팅·저장소·commit 이력을 다시 조사하지 않습니다.
- 현재 작업, 확인된 결과, 남은 조건, 다음 행동을 대상 형식의 짧은 문장으로 갱신합니다. 직접 검증·담당 보고·과거 기록·미확인을 구분하고 기능 체크박스·전체 작업 큐·완료율을 복제하지 않습니다.
- 대표 상태는 대상 형식이 정한 기존 상태 의미를 사용합니다. 표에서는 첫 열 맨 앞에 `이모지 + 공백 1칸 + 한국어 상태 텍스트`를 유지합니다. 검사 실패, 사용자 작업 중단, 대기·검토 필요를 구분하며 색상을 우선순위로 사용하지 않습니다.
- 준비·작성·빌드·설치·게시·실제 적용·기능 완료를 확인한 범위로 표현합니다. 앱의 active·idle 표시나 오래된 보고 시각만으로 진행·중단·Goal 상태를 판정하지 않습니다.
- 보고 시각은 해당 보고의 시각, 원본 확인 시각은 실제 읽은 시각, 요약 갱신 시각은 실제 수정 시각입니다. 대상이 ISO 8601을 사용하면 시간대를 포함합니다. 모르는 보고 시각은 `미확인`으로 유지합니다.
- 사용자 행동은 근거로 확인된 없음, 미확인, 실제 필요한 행동을 구분합니다. 기존 미해결 행동은 최신 근거로 해소된 경우에만 제거합니다. 안내가 미준비인 경우 행동 없음으로 바꾸지 않습니다. 마지막 열에는 실제 행동 안내만 연결하고 PLAN·TODO·결과 문서를 행동 안내로 대신하지 않습니다.
- 근거는 기존 소유 원본·검증 기록에 연결합니다. 개인 절대 경로·채팅 ID·자격증명·원형 보고는 공개 카드에 넣지 않습니다.

쓰기 직전 카드의 변경을 재확인하고 다른 작성자의 최신 변경을 보존합니다. 충돌하는 카드만 조율하며 독립 작업은 이어갑니다.

## 3. 집계와 검증

- 지정 통합 담당만 대상 사용법이 정한 기존 생성기로 전체 현황판을 갱신합니다. 다른 담당은 카드 결과를 반환하고 공유 표를 직접 고치지 않습니다. 기존 생성기를 skill 안에 복제하지 않습니다.
- 담당 수는 현재 공식 배정에서 확인합니다. 대상 도구가 지원하면 예상 수·중복 담당·필수 필드·상태·시각을 검사합니다. 동일 입력의 출력 일치와 오류 시 기존 출력 보존은 기존 통과 근거를 재사용하고 도구 변경·실패가 있을 때 영향 범위만 검증합니다.
- 변경된 카드·현황판의 표현, 첫 열 상태, 사용자 행동 구분, 링크·헤딩·앵커를 대상의 지정 검사기로 확인합니다. 기계 검사 위임은 현재 개인 지침의 모델 기준을 따릅니다. 검사기 부재·대상 0개·미실행과 검사 통과를 구분합니다.
- 실패하면 원인과 해당 입력·진단을 보존하고 영향 범위만 교정합니다. 이전 정상 현황판과 다른 담당 변경을 보존하며 기능 작업의 실패로 확대하지 않습니다.
- staging·commit·push는 기존 게시 담당·권한·묶음 단위를 따릅니다. 카드 갱신을 새 Goal·자동 감시·다른 채팅 메시지·skill 설치·모델 설정 변경의 권한으로 해석하지 않습니다.

## 4. 결과와 적용 확인

갱신한 실제 파일, 현재 확인 시각, 검증 범위와 남은 조건을 짧게 반환합니다. 이미 준비된 실제 사용자 행동만 맨 위에 모으고, 표를 쓰면 대표 상태를 첫 열에 둡니다.

개인 skill 설치·파일 일치, 세션의 목록 발견·선택·본문 읽기, 실제 카드 갱신·통합 집계는 별도로 확인합니다. 기존 채팅·새 채팅·새 프로젝트에서 관찰한 범위만 적용 완료로 보고합니다. 자동 선택 허용은 상시 실행이나 모든 프로젝트의 현황판 등록을 뜻하지 않습니다.
