
# 인프라 명세

## 명세에서 구현까지

명세 → 기술 계획 → 실행 과제 → 요청된 구현 순서로 각 단계의 요구·계약을 검토합니다. 명확한 최소 태그·파라미터 변경까지 별도 명세를 강제하지 않습니다. 명세 작성만으로 구현·운영 적용·게시·Goal을 시작하지 않습니다.

먼저 가정을 명시하고 확인된 자료·미확인 결정과 구분합니다. 예시의 네트워크 대역·지역·버전·비용을 사실로 채택하지 않습니다. 실제 도구·버전·계정·대상 Windows 버전·실행 주체를 기록합니다. 현재 값·권장 설정은 공식 출처와 실제 자료로 확인합니다.

[명세 양식](../windows/spec-template.md)에서 목적, 현재 상태, 목표 상태, 기술·리소스·의존성, 영향 범위, 보안, 모니터링, 비용, 권한·경계, 성공 기준, rollback과 미결 사항을 필요한 수준으로 작성합니다. 운영 상태 변경 전 상태를 보존하는 복구 계약을 포함합니다.

## 계획과 구현 연결

명세가 정리되면 모듈·의존성 그래프·환경별 적용 순서·위험 대응을 계획합니다. 실제 과제 분해에는 ID·선행 조건·완료 기준·검증·사용자 개입 조건을 연결합니다. 별도 PLAN/TODO 작성이 요청됐다면 제공된 planning-and-breakdown을 사용하고, 미제공이면 실제 사용했다고 주장하지 않습니다. 단독 명세 작성에는 형제 스킬 설치를 요구하지 않습니다.

구현이 요청된 범위만 작은 논리 변경으로 나누어 영향 계획·승인된 적용·실제 검증을 수행합니다. 결정·범위 변경을 명세에 반영하고 저장소가 채택한 기록·버전 관리 경로를 따릅니다.

## 복구 계약

신규 설치의 제거와 기존 설치의 업그레이드 복원을 구분합니다. 변경 전 미설치인 패키지만 제거가 원상 복구일 수 있습니다. 기존 설치는 이전 버전·구성·의존성으로 복구하고 구성만 바뀌었다면 패키지를 제거하지 않습니다.

서비스·ACL·인증서·데이터·엔진의 이전 상태와 실제 복구 수단을 각각 확인합니다. 엔진 변경 전 앱·driver·데이터 호환성을 준비합니다. state 값 변경만으로 실제 리소스·데이터가 복원된다고 가정하지 않습니다.

명세 완료는 검토 가능한 요구·계약의 완성을 뜻합니다. 실제 plan/apply·건강 검사·보안 감사는 별도 구현 단계의 실행 근거이며 미실행을 통과로 쓰지 않습니다.
## 실행 기준

현재 사용자 요청·적용 저장소 지침·플랫폼 정책과 실제 권한을 따릅니다. 저장소 작업은 실제 Git 루트·기존 변경·하위 지침부터 확인하고 다른 작업과 비공개 자료를 보존합니다. 검토·명세 작성은 설치·운영 적용·게시 권한을 추가하지 않으며 이미 승인된 범위는 반복 확인하지 않습니다.

Windows PowerShell을 사용하고 파일 작업은 확인한 절대 경로와 `-LiteralPath`로 처리합니다. Python이 필요한 경우 실제 Python 3.11 이상을 확인해 `python -X utf8 -B`로 호출하고 UTF-8 입출력을 명시합니다. PowerShell 오류와 외부 명령의 `$LASTEXITCODE`를 각각 판정합니다. 업무에 필요한 선택 도구만 실제 설치·대상·권한을 확인하며 자동 설치하지 않습니다. Windows 네이티브에서 실행할 수 없는 기능은 범위 밖으로 표시합니다.

한국어로 결과와 실제 근거를 보고하고 통과·부분 검사·실패·미실행을 구분합니다. 폴더 안의 해당 참조만 필요할 때 읽으며 다른 저장소·형제 스킬 설치를 필수로 요구하지 않습니다.
