# 저장소 Workflow와 AI 산출물 관리

재사용 개인 규칙의 상세 참조입니다. 지속 작업·문서 구조 설계·작업 재개·산출물 정리에 필요할 때 읽으며 모든 질문에 전체 문서와 빈 폴더를 생성하지 않습니다. 상태와 이력은 각 실제 Git 저장소 안에서 관리합니다.

## 1. 적용 기준과 발견

현재 사용자 요청·적용 저장소 지침·실제 도구 계약을 우선합니다. 기존 관리 경로를 먼저 재사용하고 관리 폴더 이름이나 게시 branch를 모든 저장소에 강제하지 않습니다. `AI_WORKSPACE`는 선택 가능한 이름이며 Codex 예약 디렉토리가 아닙니다.

AGENTS는 적용 지침, SKILL의 name·description은 선택 정보, 선택한 SKILL 본문은 실행 절차입니다. INDEX·PLAN·TODO·TASK·REVIEW 등의 일반 문서는 기본 자동 발견 이름이 아닙니다. repo AGENTS에서 관리 진입점과 INDEX 조회 조건을 연결합니다. INDEX를 AGENTS fallback 목록에 추가하여 두 문서를 함께 읽는 방식으로 설명하지 않습니다. [공식 AGENTS 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [공식 skill 안내](https://learn.chatgpt.com/docs/build-skills)

다운로드 사본·캐시·설치·현재 세션 목록·자동 선택·행동 검증을 구분합니다. 공식 예제도 현재 도구·OS·의존성과 대조합니다. 없는 도구 이름을 호출하거나 같은 이름의 skill을 임의로 선택하지 않습니다. plugin/skill 이름과 실제 파일 경로를 함께 식별하되 표시용 구분을 새 호출 문법으로 주장하지 않습니다.

## 2. 문서의 기준 원본

| 문서       | 역할                                                                     |
|------------|--------------------------------------------------------------------------|
| README     | 사람에게 개요·사용법·관리 진입점을 안내                                  |
| INDEX      | 주요 경로 tree·작업별 읽을 문서·skill·읽는 조건·결과/검증 원본 연결      |
| PLAN       | 큰 목표·범위·단계·완료 기준·채택한 결정                                  |
| TODO       | 활성 작업 ID·내용·상태·담당·다음 행동의 기준 원본                        |
| TASK       | 작업별 범위·입력·완료 기준·결과물·검증 링크; TODO의 상태를 반복하지 않음 |
| REVIEW     | 대상·기준 commit·사실/추론·잘된 점/문제·근거·한계·후속 조치              |
| ISSUE      | 재현·원인·해결·검증·재발 방지·다음 세션 재개 방법                        |
| CHANGELOG  | 완료 요약과 상세 이력 연결; 기존 제품 release 로그의 용도를 존중         |
| DELEGATION | 복잡한 위임의 범위·입력·모델·완료 조건·총괄 검토                         |
| INTERVIEW  | 미확정 질문·관점·대안; 채택한 결정은 PLAN에 연결                         |

INDEX는 필요할 때 추가합니다. README의 전체 설명·TODO 상태·skill 본문·모든 파일 목록을 다시 복사하지 않습니다. 기존 skill router가 있으면 그 기준 원본으로 연결합니다. tree는 주요 관리 경로와 관련 작업만 설명하고 생성/이동 시 필요한 링크를 갱신합니다.

기본 방식은 짧은 TODO.md와 큰 작업의 tasks/<ID>/TASK.md입니다. 작은 작업은 TODO 한 항목과 최종 보고로 끝낼 수 있습니다. TODO/ 디렉토리를 선택하면 각 작업 문서를 상태 원본으로, TODO/README.md를 ID·제목·링크 색인으로 사용하며 별도 TODO.md에 같은 상태를 중복 기록하지 않습니다. 완료 뒤에도 같은 경로에서 작업 상세를 유지하려면 tasks/라는 이름이 적절합니다.

도구의 JSON·실행 manifest·외부 tracker는 실행 ID·객체 ID·검증 결과 등 그 도구 내부 상태의 원본일 수 있습니다. TODO가 이를 대체하거나 수정하지 않습니다. TODO에는 사용자 작업의 요약 상태와 실제 원본 연결만 관리합니다.

## 3. 작업별 디렉토리와 경로 예외

다음은 선택 구조입니다. 기존 관리 폴더가 있으면 그대로 쓰고 tasks·outputs·evidence·local은 실제 필요할 때만 생성합니다. 작업이 많으면 주제 층을 추가할 수 있습니다.

```text
<repo>/<기존 관리 폴더>/
├── INDEX.md
├── TODO.md
├── tasks/
│   └── T-001-이펙트효과복원/
│       ├── TASK.md
│       ├── outputs/      # 자유롭게 저장 위치를 정할 수 있는 최종 결과
│       └── evidence/     # 해당 검증의 공개 가능한 근거
├── history/              # 완료된 관리 기록
└── local/                # 비공개 raw·scratch: 해당 경로를 Git 제외
```

일반 관리 기록과 위치를 지정할 수 있는 결과물은 repo 관리 공간에 모읍니다. 선택 skill·도구·기존 프로젝트의 고정 경로, sealed scan bundle, 제품에서 사용하는 소스·자산·DB·빌드 파일은 자동 이동하지 않습니다. 지정한 출력 옵션이 실제 지원되는지 확인하고, 경로를 유지해야 하면 TASK/INDEX에서 실제 위치나 외부 최종 URL을 연결합니다.

예를 들어 product-design의 프로젝트 루트 design-qa.md, skill이 정한 output/pdf/, 도구가 관리하는 임시 scan bundle·plugin persistence는 각 계약을 유지합니다. 개인 전역 설정·skill 설치 경로는 repo 작업 상태의 저장소가 아닙니다. skill의 assets/는 재사용 템플릿·아이콘·소재이며 작업별 결과물을 누적하는 폴더로 사용하지 않습니다.

제품이 참조하는 최종 결과는 제품의 정식 경로에 두고 관리 공간에서 연결합니다. 임시 생성 위치에만 의존하지 않도록 결과·소비자 참조를 확인합니다. 고객용 최종 문서에 내부 관리 경로를 억지로 넣지 않습니다. 로컬 사용자 보고에는 실제 경로를, 공개 기록에는 공개 가능한 상대 경로·별칭을 사용합니다.

## 4. 완료·검증·재개

작업 ID는 repo 안에서 유일하게 유지합니다. 완료 기준을 확인하고 공개 가능한 상세 관리 기록을 같은 repo의 history 또는 기존 완료 기록에 먼저 보존한 뒤 CHANGELOG에 요약·연결을 남깁니다. 들어오는/나가는 링크와 앵커를 확인한 뒤 완료 항목을 활성 TODO에서 제거합니다. 미완료·사용자 검증 대기 항목은 유지합니다.

작업의 산출물·검증 원본은 안정적인 경로에 유지하고 history에서 연결합니다. sealed·도구 관리 자료를 이력 정리 때문에 수정·이동하지 않습니다. raw·비공개 자료는 로컬에서 보존하고 Git 제외가 실제 적용됐는지 확인하며, 경로 이름만으로 비공개라고 판정하지 않습니다.

이전 history·cache의 검사를 현재 검증으로 바꾸지 않습니다. 대상 commit·입력·실제 실행·정적 확인·실패·미실행·검증 원본을 구분합니다. 같은 항목의 상세 내용을 REVIEW/CHANGELOG/INDEX에 각각 독립 원본으로 만들지 않습니다.

이미 승인된 작업에 같은 승인 질문을 반복하지 않습니다. 문서 정리·공개 예제·과거 승인으로 외부 앱 쓰기·설치·배포·다른 repo 변경의 권한을 확대하지 않습니다. Git 게시는 현재 사용자와 repo가 정한 순서를 따릅니다. 필요한 경우 ISSUE에 다음 세션의 실제 재개 조건을 남깁니다.

## 5. 참고 원본과 개인 skill 교체 기록

재사용 실행본은 관리하는 플랫폼별 skill 폴더에 두고, `_reference`에는 출처·commit·확인일·수정 차이와 필요한 외부 원본을 연결합니다. 외부 clone은 URL과 사용 목적이 확인된 경우에만 수행하며 내부 skill의 중복 clone이나 참고 캐시를 자동 실행본으로 쓰지 않습니다. 각 skill은 필요한 참조를 동봉해 독립 사용을 유지합니다.

개인 skill 교체는 변경 전 전체 폴더·해시·출처·사용자 차이를 보존한 뒤 수행합니다. 새 본문의 해시·내부 링크·실제 설치 위치를 확인하고 성공한 동명 교체의 이전본만 발견 경로에서 정리합니다. 교체되지 않은 별도 skill, system·plugin·설정 파일은 지정 범위를 따릅니다. 복구는 보관한 폴더와 설치 기록을 대조하며 진행 중 사용자 변경을 덮어쓰지 않습니다.

개인 Codex 설정의 업데이트별 백업을 폴더 단위로 지정했다면 기존 관리 공간의 Codex 영역 아래 `<날짜>-<목적>-<작업ID>/` 하나에 README·변경 전/후 skill 사본·inventory·검증·복구를 묶습니다. 다음 업데이트는 새 이름으로 추가하고 예전 사본·JSON을 덮어쓰지 않습니다. 실제 AGENTS·config·개인 경로가 있는 raw 기록은 그 업데이트 폴더의 Git 제외가 확인된 private/에 보관합니다. 공개 기록은 환경 별칭·이름·상대 파일 해시·출처·실행/미실행을 연결하며 전체 홈·인증·키·세션을 복제하지 않습니다. 일반 작업의 기존 tasks/history 체계와 고정 경로는 유지하고 폴더 배치를 새 세션 발견·자동 선택 성공으로 표시하지 않습니다.
