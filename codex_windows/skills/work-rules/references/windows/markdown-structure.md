# Markdown 문서 구조 기준

대상 저장소가 채택한 문서 형식을 먼저 확인합니다. 아래는 지정이 없는 경우의 개인 기본값이며 문서 역할·양식·상태 정책을 재정의하지 않습니다. 검사는 동봉 도구의 실제 출력과 범위를 근거로 판정합니다.

## 앵커

GitHub 앵커는 소문자 변환, 해당 구두점·기호 제거, 공백의 하이픈 변환 순서로 만들어집니다. 한글·숫자·하이픈·밑줄은 유지됩니다. 연속 공백은 각각 하이픈으로 바뀌며 장식 기호를 지웠다고 연속 하이픈을 축약하지 않습니다. 유니코드 범위가 넓으므로 간이 정규식으로 재현하지 말고 동봉 헤딩 검사기의 앵커 결과를 사용합니다. 실제 헤딩 등장 순서에 따라 중복 suffix도 대조합니다.

| 헤딩                      | 앵커 예시                 |
|---------------------------|---------------------------|
| `TIME_WAIT`               | `#time_wait`              |
| `컨텍스트 / 도구 상세`    | `#컨텍스트--도구-상세`    |
| `토큰 절약 & 성능 최적화` | `#토큰-절약--성능-최적화` |
| `CI/CD 비대화형`          | `#cicd-비대화형`          |
| `B-Tree / B+Tree 구조`    | `#b-tree--btree-구조`     |

헤딩 끝의 장식용 괄호·기호는 제거 뒤 하이픈을 남길 수 있습니다. 제목의 의미를 보존하는 범위에서 장식을 줄입니다. 같은 제목의 헤딩은 첫 앵커 뒤에 `-1` 등 suffix가 붙으므로 의도한 헤딩을 가리키는지 확인합니다. 릴리스마다 반복되는 `### Added`처럼 참조하지 않는 중복은 형식상 정상일 수 있으며 중복 정책과 앵커 존재를 구분합니다.

## 목차

목차가 있는 문서는 코드블록 밖의 H2 목록과 목차 링크를 대조합니다. 기본 제외는 `목차`, `참고 자료`, `통계`, `참고 URL`이며 실제 저장소의 예외가 우선합니다. 목차 링크는 실제 H2를 가리켜야 합니다. 코드 예시 안의 `## 헤딩`을 목차에 넣지 않습니다.

추가·수정·삭제한 H2가 목차에 반영됐는지, 모든 링크 앵커가 실제 대상과 맞는지 확인합니다. 도구가 출력한 검사 범위 밖의 목차 요구는 직접 대조하고 자동 검증 완료로 보고하지 않습니다.

## H2 번호

목차가 있고 번호 체계를 사용하는 문서는 H2를 `1.`부터 빠짐없이 연속 부여합니다. 고정 섹션 `목차`, `참고 자료`, `통계`와 README의 `문서 목록`, `문서 트리`, OS·레이어·연차 분류는 번호에서 제외할 수 있습니다. `1단계:`, `Phase 1`처럼 단계 번호가 이미 있으면 중복 번호를 붙이지 않습니다.

OS·버전별 문서, 레이어·프로토콜별 문서, 비교·분석 문서, README 인덱스와 원문 보존 기능 목록은 전체 H2 번호가 필요하지 않을 수 있습니다. 대상 양식에 맞추며 검사 통과를 위해 문서 역할을 바꾸지 않습니다.

| 표기            | 의미                   | 카운터              |
|-----------------|------------------------|---------------------|
| `## 5-10. 제목` | 규칙 5부터 10까지 포괄 | 끝 번호 10으로 진행 |
| `## 1-1. 제목`  | 직전 1절의 하위 항목   | 진행하지 않음       |

뒤 숫자가 앞보다 크면 범위, 작거나 같으면 하위 절입니다. 하위 절 뒤에는 원래 번호 순서가 이어집니다.

## 헤딩과 강조

헤딩은 한 단계씩 내려갑니다. H2 뒤에 바로 H4를 쓰지 않습니다. 외부 프로젝트 원문을 보존하는 예외는 실제 `.md-heading-check.toml`의 `[[file_skip]]` 등에 사유와 범위를 기록할 때만 적용합니다. 숨길 목적으로 임의 제외하지 않습니다.

`**가상 테이블(Virtual Table)**이다`처럼 닫는 강조 뒤에 한글이 바로 이어지면 일부 파서에서 표현이 깨집니다. `**가상 테이블(Virtual Table)** 이다`처럼 공백을 둡니다.

## 코드 펜스

중첩 코드블록 예시는 외부 펜스를 내부보다 길게 씁니다. 내부가 3-backtick이면 외부는 4-backtick을 사용합니다. 여는 펜스의 문자·길이를 추적하며 같은 문자로 같거나 더 긴 펜스와 뒤 공백만 있을 때 닫힙니다. 언어 태그가 붙은 줄, 다른 펜스 문자, 짧은 펜스는 내용입니다. 최대 3칸 들여쓴 펜스와 tilde 펜스도 확인하며 4칸 이상 들여쓰기를 같은 여는 펜스로 보지 않습니다.

닫히지 않은 펜스를 경고만 있는 통과로 처리하지 않습니다. 코드블록 뒤의 실제 링크·헤딩까지 검사됐는지 확인합니다.
