
# 점진적 변경

## 변경 단위

각 단위는 최소 논리 변경 → 영향 계획 → 승인된 적용 → 실제 검증 → 저장소 규약에 따른 기록·commit → 다음 단위 순서로 진행합니다. 코드 수정·계획만 요청받았으면 운영 적용 단계를 실행하지 않습니다. 각 단위가 끝날 때 정상 상태와 복구 가능성을 유지합니다.

| 분할 기준   | 선택 조건                                                                |
|-------------|--------------------------------------------------------------------------|
| 의존성 우선 | 네트워크 기반 → 접근 규칙 → 실행 리소스 → 연결·건강 검사                 |
| 위험 우선   | 의존성과 호환성이 준비된 변경 사이에서 위험한 부분을 먼저 조사·격리 검증 |
| 환경 우선   | 개발 → 검증 → 운영 환경별 차이와 성공 기준을 확인                        |

엔진 업그레이드 전에 앱·driver·데이터·연결의 구버전/신버전 호환성을 준비합니다. 위험도가 높다는 이유로 선행 의존성을 뒤로 미루지 않습니다.

## 적용과 검증

각 적용 전에 대상·예상 변경·중단 조건·rollback을 확인합니다. 여러 무관한 접근 규칙·DB·컴퓨팅 변경을 한 적용에 묶지 않습니다. 실제 건강·리소스 상태·지표와 변경 정합성을 확인한 뒤 다음 단위로 넘어갑니다. 실패하면 추가 변경을 멈추고 증거 보존·원인 조사·복구 검증을 수행합니다.

IaC 관리 리소스는 승인된 관리 경로로 변경합니다. 긴급 수동 변경이 실제 승인됐다면 그 상태를 관리 원본과 대조해 드리프트를 남기지 않습니다. 코드 복귀만으로 데이터·엔진·리소스가 복원된다고 가정하지 않습니다.

Terraform을 사용하는 업무에만 [Terraform 상세](../windows/terraform.md)를 읽습니다. Windows 네이티브에서 지원되지 않는 제어 기능의 실제 실행은 범위 밖이며 다른 환경을 자동 설치·호출하지 않습니다.

완료 보고는 단위별 코드 변경·실제 적용·검증·commit 여부를 구분하고 최종 정합성·건강·모니터링·복구 계획의 실제 근거를 남깁니다. 적용하지 않은 도구의 검사를 완료 조건으로 강제하지 않습니다.
## 실행 기준

현재 사용자 요청·적용 저장소 지침·플랫폼 정책과 실제 권한을 따릅니다. 저장소 작업은 실제 Git 루트·기존 변경·하위 지침부터 확인하고 다른 작업과 비공개 자료를 보존합니다. 검토·명세 작성은 설치·운영 적용·게시 권한을 추가하지 않으며 이미 승인된 범위는 반복 확인하지 않습니다.

Windows PowerShell을 사용하고 파일 작업은 확인한 절대 경로와 `-LiteralPath`로 처리합니다. Python이 필요한 경우 실제 Python 3.11 이상을 확인해 `python -X utf8 -B`로 호출하고 UTF-8 입출력을 명시합니다. PowerShell 오류와 외부 명령의 `$LASTEXITCODE`를 각각 판정합니다. 업무에 필요한 선택 도구만 실제 설치·대상·권한을 확인하며 자동 설치하지 않습니다. Windows 네이티브에서 실행할 수 없는 기능은 범위 밖으로 표시합니다.

한국어로 결과와 실제 근거를 보고하고 통과·부분 검사·실패·미실행을 구분합니다. 폴더 안의 해당 참조만 필요할 때 읽으며 다른 저장소·형제 스킬 설치를 필수로 요구하지 않습니다.
