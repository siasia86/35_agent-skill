# 계획 분해·양식·검증

## 의존성과 실행 단위

현재 상태를 읽기 전용으로 조사하고 기능·환경·도구·권한 의존성을 연결합니다. 예를 들어 네트워크·서브넷·접근 정책이 서비스보다 앞서고 서비스 준비가 대상 등록과 상태 확인보다 앞섭니다. 특정 제품의 구성도를 모든 계획에 적용하지 않습니다.

정상 상태를 유지하는 기능 단위를 우선합니다. 웹 기능의 접근 정책·실행 환경·라우팅·상태 확인을 하나의 검증 가능한 단계로 묶고 앱·데이터 기능은 각각 선행 조건을 따릅니다. 환경 변경은 개발·검증·운영 단계별 검증과 복구를 연결합니다.

| 크기 | 기존 분해 참고 규모       | 판단                          |
|------|---------------------------|-------------------------------|
| S    | 리소스 1~3개·단일 서비스  | 범위가 명확하면 직접 처리     |
| M    | 리소스 4~8개·한 기능 계층 | 선행 조건과 독립 검증 연결    |
| L    | 리소스 9~15개·여러 계층   | 더 작은 정상 상태 단위로 분할 |
| XL   | 리소스 15개 이상          | 분할 필요                     |

숫자는 분해 참고 기준이며 실제 위험·의존성·검증 가능성이 우선합니다. 리소스 수가 적어도 위험이 높으면 별도 단계가 필요하고 규모가 큰 태스크를 완료 조건 하나로 묶지 않습니다.

## PLAN 골격

아래에서 필요한 부분을 대상의 양식에 맞춰 작성하고 기존 ID·사용자 편집·보류를 보존합니다. 빈 문서·절을 일괄 생성하지 않습니다.

```markdown
# 변경 계획: 제목

## 목표와 범위

무엇을 왜 변경하는지, 포함·제외 범위와 현재 사용자 제한을 적습니다.

## 현재 상태와 목표 상태

확인한 근거와 미확인 조건을 구분합니다.

## 실행 순서와 의존성

기존 작업 ID와 소유 담당, 선행 조건을 연결합니다.

## 완료 조건과 검증

작업별 관찰 가능한 조건·실행 도구·예상 결과·미실행 처리 기준을 적습니다.

## 영향과 복구

영향 서비스·환경·다운타임·데이터·복구 가능한 범위와 절차를 적습니다.

## 사용자 개입과 미결 사항

필요 입력·선택·명시 보류 해제·재개 조건을 적습니다.
```

## 태스크 골격

```markdown
### 작업 ID: 제목

- 목적: 이 작업이 완료하는 기능이나 명세
- 담당: 소유 담당과 실제 대상 작업본·브랜치
- 입력: 실제 파일·자료·버전 또는 해시
- 범위: 담당 파일·제외 파일·영향 환경
- 선행 조건: 기존 작업 ID 또는 없음
- 실행: 실제 플랫폼·도구·명령·권한 범위
- 완료 조건: 관찰 가능한 결과
- 검증: 도구·대상·예상 결과·종료 상태
- 복구: 증거 보존과 되돌릴 수 있는 범위
- 사용자 개입: 필요한 조건·입력·재개 행동
- 다음 행동: 현재 준비된 단계
- 완료 근거: 실제 실행·검증 결과와 링크
```

## 체크포인트와 검증

의존성 순서대로 실행하고 단계 후 시스템 정상 상태를 확인합니다. 위험한 단계는 선행 호환성·접근 조건을 충족한 시점에 조기 검증합니다. 체크포인트 개수는 위험과 범위에 맞추며 태스크 2~3개마다 일률적으로 사용자 승인을 요구하지 않습니다.

실제 Terraform 작업이라면 예상 변경만 있는 plan, 승인된 apply 결과, 서비스 상태·모니터링을 확인합니다. 계획 작성만 요청되면 apply를 실행하거나 배포 성공으로 표시하지 않습니다. `terraform plan -detailed-exitcode`처럼 변경 있음을 뜻하는 정상 상태는 실제 도구 계약으로 판정합니다. 정상 서비스와 계획 변경 없음은 항상 같은 조건이 아니므로 목표에 맞는 기대 결과를 적습니다.

PowerShell cmdlet 오류와 네이티브 CLI의 `$LASTEXITCODE`를 구분합니다. Python이 필요한 실제 검사는 Python 3.11 이상의 `python -X utf8 -B`를 사용하고 파일 입출력에 UTF-8을 명시합니다. 실제 런타임·도구·권한 부재는 선행 조건이나 미실행으로 기록하고 설치·ACL·운영 권한 변경을 자동 수행하지 않습니다.

## 점진적 변경과 실패 복구

구현까지 요청되면 현재 상태와 복구 범위를 보존하고 한 번에 검증 가능한 변경만 반영합니다. diff와 실제 관찰을 대조한 뒤 다음 준비된 단계로 진행합니다. 공유 파일은 단일 담당과 통합 순서를 유지합니다.

실패 시 영향 구간을 멈추고 입력·명령·종료 코드·로그·현재 상태를 보존합니다. 가설을 실제 근거로 확인하고 원인을 교정한 뒤 영향 범위를 재검증합니다. 이미 통과한 전체 검사를 새 근거 없이 반복하거나 원인 분석 전에 사용자 반복 시험을 요청하지 않습니다. 다른 독립 작업은 계속 진행합니다. 운영 상태·권한·비공개 자료를 공개 기록에 복사하지 않습니다.
