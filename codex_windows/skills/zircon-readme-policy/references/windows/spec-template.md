# Windows 인프라 명세 양식

문서 역할·위치·양식은 대상 저장소 기준을 사용합니다. 이 양식은 실제 업무에 맞춰 필요한 세부 항목을 채웁니다.

| 항목        | 작성할 내용                                                   |
|-------------|---------------------------------------------------------------|
| 목적·범위   | 해결할 문제, 요구, 제외 범위, 현재 승인                       |
| 현재·목표   | 관찰한 구조, 변경 후 구조와 주요 연결                         |
| 실행 환경   | 실제 Windows 버전·PowerShell·Python, 업무 도구·버전·실행 주체 |
| 리소스·구성 | 이름 규칙·수량·의존성, 서비스·패키지·파일·인증서의 대상       |
| 네트워크    | 실제 대역·이름·연결·포트·충돌과 접근 주체                     |
| 보안        | 최소 권한·비밀 관리·암호화·격리·감사, 필요한 실제 ACL         |
| 관찰        | 로그·건강·지표·중단 기준·승인된 알림 경로                     |
| 영향·비용   | 서비스·사용자·중단 시간·비용 근거와 미확인 가정               |
| 경계        | 항상 지킬 계약, 추가 결정이 필요한 동작, 금지된 동작          |
| 검증        | 재현 가능한 성공·실패 기준, 실제 runner·fixture·대상          |
| 복구        | 변경 전 상태, 백업·이전 버전·구성·데이터, 복구 순서·검증      |
| 미결        | 확인할 근거·담당·선행 조건·사용자 결정                        |

설정 자동화는 대상 파일·입력·생성 규칙·재실행 멱등성·부분 실패·서비스 재시작 필요성을 기록합니다. 신규 설치·기존 업그레이드·설정 변경을 구분해 실제 원상 복구를 정합니다. 이전 버전/백업이 없다면 있다고 가정하지 않습니다.

Windows에서 실행하지 못하는 제어 기능은 이 실행 범위 밖으로 표시합니다. 지원되지 않는 모듈·접속·권한 모델을 Windows 기능으로 이름만 바꾸지 않습니다. 명세 작성에 도구 설치·실제 인증 변경·운영 적용을 포함하지 않습니다.

단계별 과제는 ID / 소유 대상 / 선행 조건 / 수행 / 검증 / 완료 근거 / 실패·사용자 개입 조건을 연결합니다. 위험도만으로 의존성을 무시하지 않습니다. 환경마다 데이터·접근·구성을 검증하며 명세·계획의 완료를 운영 검증 완료로 쓰지 않습니다.
