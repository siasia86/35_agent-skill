# 경계·실패 조건 시험

정상 흐름을 기준으로 입력·환경·상태·시간·자원 조건이 달라질 때 실제 계약이 유지되는지 검증합니다. 해당 업무에 필요한 축만 읽고 적용하며 모든 축을 무조건 운영 장애 주입으로 실행하지 않습니다.

## 개념

| 용어            | 뜻                                                |
|-----------------|---------------------------------------------------|
| Edge case       | 유효 범위 경계: 첫/마지막·빈 파일·최대 연결       |
| Corner case     | 여러 경계가 겹침: 저장 실패와 연결 단절           |
| Boundary value  | 수치 min/max와 바로 아래·위                       |
| Degenerate case | None·빈 목록·단일 요소처럼 극단적으로 단순한 입력 |
| Error case      | 잘못된 타입·권한 없는 경로·만료 토큰              |
| Race condition  | 동시 실행·역순 처리에서 발생하는 시점 의존 충돌   |
| Happy path      | 유효 입력·정상 연결·충분한 자원의 비교 기준       |

경계값 분석은 수치 min/max 주변을 다루며 경계·실패 조건 시험은 환경·상태·시간·자원까지 넓힙니다. min-1/min/min+1/max-1/max/max+1과 동등 분할을 실제 입력 계약에 맞춰 선택합니다.

## 5축 도출

| 축   | 질문·대표 조건                                    |
|------|---------------------------------------------------|
| 입력 | 빈값·최대 길이·잘못된 타입·특수문자·Unicode·개행  |
| 환경 | 디스크·메모리 부족·DNS 실패·연결 손실·느린 응답   |
| 상태 | 초기화 전·부분 쓰기·중간 실패·재시작·cold start   |
| 시간 | 동시 쓰기·중복 요청·만료·timeout·역순 이벤트      |
| 자원 | 파일 핸들·프로세스·connection pool·할당 한도·경합 |

정상 흐름에 각 적용 축의 경계·실패 조건을 결합합니다. 축마다 의미 있는 대표 조건을 고르고 다중 조건이 중요하면 corner case를 추가합니다. 실제 비적용 축은 이유만 남깁니다.

## 인프라 조건

| 계층     | Windows에서 확인할 기능                                                                   |
|----------|-------------------------------------------------------------------------------------------|
| 네트워크 | 단절 후 재연결·DNS 실패·packet 손실·느린 대역의 timeout·재시도·멱등성                     |
| 저장     | 디스크/할당 한도·다수 작은 파일·읽기 전용/ACL 거부·공유 저장소 지연의 오류·정리·원본 보존 |
| 프로세스 | 중복 실행 조율·남은 자식/핸들·메모리 부족·서비스 재시작 반복의 제한·진단                  |
| 권한     | 일반 계정의 오류 전달·토큰 만료·실제 ACL/보안 정책 차단과 필요한 이벤트 근거              |

Windows 네이티브에서 실행되지 않는 기능은 범위 밖입니다. 다른 플랫폼의 inode·프로세스·서비스·보안 모듈을 Windows의 동등 보장으로 주장하지 않습니다. 실제 서비스·네트워크를 변경하는 장애 주입은 명시한 대상과 승인 범위에만 수행합니다.

## 스크립트·파일·동시성

- 입력은 None·빈값·한글/Unicode·공백·달러 기호·backtick·대용량·LF/CRLF를 검증합니다. PowerShell 인수와 Python `pathlib`·명시 UTF-8을 사용하고 경로를 셸 코드로 재해석하지 않습니다.
- 파일 없음·빈 파일·읽기 전용·ACL 거부·symlink/reparse/junction·순환 경로·공유 잠금·replace 실패를 지원 계약과 대조합니다. 거부할 경로를 조용히 허용했다고 보고하지 않습니다.
- 중복 실행은 실제 잠금·세션 소유·멱등성으로 조율합니다. 검사 후 생성 경쟁, 잠금 생성 중 실패, 타인/손상/노후 잠금, 남은 guard와 파일 교체를 구분합니다.
- 부분 쓰기·임시 파일 flush/교체 실패·중단 뒤 원본·임시 자료·핸들 정리를 검증합니다. Ctrl+C와 강제 종료의 정리 보장은 같지 않습니다. 부모 종료 후 자식 프로세스 처리도 실제 계약을 확인합니다.
- 파일 저장이나 잠금 자체를 시험할 때 그 파일시스템 경계를 전부 mock하지 않습니다. NTFS ACL·owner·ADS 보존과 비협조 writer까지 보장한다면 실제 구현·시험 근거가 필요합니다.

## 시험 방법

| 방법           | 선택 기준                                                             |
|----------------|-----------------------------------------------------------------------|
| 수동 재현      | 자동으로 판단하기 어려운 실제 대상의 최소 관찰                        |
| 자동화         | 반복 가능한 BVA·동등 분할·회귀와 저장소 runner                        |
| Mock/Stub      | 외부 의존의 DNS 실패·timeout·권한 오류·저장 실패를 제한된 경계에 주입 |
| 격리 장애 주입 | 전용 fixture·임시 작업본에서만 자원/정리 계약 재현                    |
| Fuzzing        | 실제 도구가 있을 때 입력 공간 탐색, seed·실패 입력 보존               |

시스템 디스크를 채우거나 운영 네트워크·권한을 바꿔 시험하지 않습니다. 표준 라이브러리 `unittest`·`unittest.mock` 또는 실제 제공된 pytest를 활용합니다. 가짜 오류 주입은 해당 경로의 오류 처리를 보여 주며 실제 디스크/공유 저장소 장애 전체를 검증한 결과와 구분합니다.

다음은 실제 검증 대상 함수가 있을 때 쓰는 표준 라이브러리 구조입니다. `validate_score`는 요청한 실제 구현을 가져오며 이 예시 자체가 동작 검증 결과는 아닙니다.

```python
import unittest

class ScoreTests(unittest.TestCase):
    def test_boundaries_and_invalid_inputs(self):
        """정상·양쪽 경계·빈 입력을 분리해 판정합니다."""
        cases = [(0, True), (100, True), (-1, False), (101, False),
                 (None, False), ('', False), (50, True)]
        for value, expected in cases:
            with self.subTest(value=value):
                self.assertEqual(validate_score(value), expected)
```

시험은 실제 Python으로 `python -X utf8 -B -m unittest discover` 등 저장소 절차에 따라 실행하고 검사 수·목적·종료 상태와 미실행을 기록합니다.

## 파서 회귀 사례

과거 중첩 박스 파서는 내부 행에 `┘`가 있다는 이유만으로 외부 박스가 끝났다고 판단해 폭 불일치를 놓쳤습니다. 이 사례는 현재 코드의 결함·교정 여부를 주장하는 자료가 아니며 중첩 입력과 파서 상태의 corner case를 도출하는 예입니다.

```python
# 잘못된 종료 조건의 예
if '┘' in line:
    end_box()

# 실제 문법이 바깥 박스의 시작/끝을 요구할 때의 조건 예
if line.strip().startswith('└') and line.strip().endswith('┘'):
    end_box()
```

회귀 fixture는 내부 `└┘`가 포함된 행, 실제 외부 종료, 폭 불일치, 인용구·fence 내부 예시를 구분합니다. 단순 문자열 일치가 상태 전이 전체를 검증했다고 확대하지 않습니다.
