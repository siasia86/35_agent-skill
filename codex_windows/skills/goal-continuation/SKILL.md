# 목표 이어가기

최신 PLAN·TODO에서 실행 가능한 승인 작업을 이어갑니다. 저장소별 기능 상태·보류·완료 조건은 소유 문서에서 읽고, 이 skill에 복제하지 않습니다. 이 폴더는 단독 사용 단위이며 다른 skill·중앙 저장소·추가 설치를 필수로 요구하지 않습니다.

## 1. 실행 전 대조

계획·검토·읽기 전용 요청에는 요청한 분석만 수행합니다. skill 호출이나 문서의 예시만으로 Goal 생성·구현·설치·게시를 시작하지 않습니다. 현재 사용자 지시·적용 저장소 지침·플랫폼 권한을 먼저 따릅니다.

목표 실행 전에 다음을 한 번 대조합니다.

- 실제 Git 루트·작업본·branch·기존 변경과 적용 AGENTS·하위 지침을 확인합니다.
- 현재 INDEX가 지정한 PLAN·TODO의 관련 큐·ID와 필요한 TASK·직접 근거를 읽습니다. 파일 존재나 게시된 다른 branch의 문서를 현행 원본으로 간주하지 않습니다.
- 목표·기존 ID·선행·담당·담당 파일·완료 조건·기존 검증·사용자 보류·승인 범위를 대조합니다. 실행 파일·도구·격리·백업·복구가 필요한 작업은 해당 준비 조건도 확인합니다.
- 다른 담당과 같은 파일·공유 데이터·GUI를 사용할 때 조율을 선행합니다. 필수 지침 접근 실패와 입력 충돌은 영향받는 작업에 기록하고, 확인된 독립 승인 작업은 계속합니다.

명백한 문서 오류는 편집이 승인된 담당 범위에서 수정·검증합니다. 검토만 요청됐으면 오류와 수정안을 보고합니다. 대조 결과는 기존 기록에 짧게 남기고 실행으로 이어갑니다. 입력·관련 변경·상충 근거가 없으면 같은 대조와 전체 skill·과거 기록 읽기를 반복하지 않습니다.

## 2. Goal 확인과 생성

실제 제공된 Goal 도구와 그 계약을 확인합니다. 기존 Goal을 조회할 수 있으면 목표·범위·완료 조건을 대조합니다.

- 같은 작업의 미완료 Goal이면 유지합니다. 완료된 Goal은 미완료 Goal처럼 재사용하지 않습니다.
- 다른 미완료 Goal은 덮어쓰거나 완료 처리하지 않습니다. 충돌과 필요한 결정을 기록하고 새 Goal 생성에 필요한 조정을 요청합니다.
- Goal이 없고 사용자가 명시적으로 생성·설정을 요청한 경우에만 생성합니다. 일반 실행·계속 요청이나 계획 작성에서 생성 승인을 추론하지 않습니다. 예산은 사용자가 명시한 경우에만 설정합니다.
- 도구가 없거나 조회가 실패하면 Goal 미생성·미확인으로 보고합니다. 실패를 Goal 없음으로 간주하지 않습니다. 승인된 일반 작업의 독립 진행 가능 여부는 현재 요청과 실제 권한으로 판단합니다.

Goal 설정은 설치·환경 변경·범위 밖 게시·운영 적용의 추가 승인이 아닙니다. 도구의 상태 변경 조건을 따르며 대기 항목 하나로 전체 Goal을 임의 중지하거나 종료하지 않습니다.

## 3. 준비된 작업 이어가기

선행·담당 충돌·사용자 보류를 확인한 뒤 실행 가능한 항목 중 가장 높은 우선순위를 선택합니다. 같은 우선순위는 PLAN 순서를 따릅니다. 작업은 저장소 별칭과 기존 ID로 구분하고 관련 기능 상태는 해당 저장소 TODO에서 유지합니다.

승인된 실행 → 자동 검증·로그 분석 → 실제 근거·상태·다음 행동 기록 → 다음 준비된 작업을 반복합니다. 이미 통과한 검사는 입력·관련 코드·도구·기대 결과 변경 또는 새 실패·상충 근거가 있을 때 영향받은 범위만 다시 검사합니다.

외부 입력·환경·선행·사용자 판정 대기는 원인·필요 입력·재개 조건·담당을 남깁니다. 대기와 충돌하지 않는 독립 자료 대조·정적 검사·다른 승인 작업을 이어갑니다. 도구·의존성 부재를 자동 설치·설정 변경으로 해소하지 않습니다.

## 4. 실패와 사용자 개입

실패하면 영향받는 단계의 로그·부분 결과를 보존하고 원인을 분석합니다. 근거 있는 수정 후 영향 범위를 재검증하고 해당 단계부터 재개합니다. 같은 조건의 실패를 반복하거나 원인 분석 없이 사용자에게 같은 시험을 다시 넘기지 않습니다.

사용자 요청 전에 가능한 자동화·도구·허용된 격리 검증을 완료합니다. 실제 권한 부족·보류 해제·필수 입력·업무상 선택·자동 판정이 어려운 사용성 확인만 모아 안내합니다. 관련 ID·필요 이유·이미 검증한 범위·최소 입력/절차·예상 결과·답 이후 행동을 함께 제시합니다.

사용자 실행 확인이 필요하면 승인된 범위에서 대상 파일·실행 환경을 먼저 준비·확인하고 절대 경로·파일명·방법을 안내합니다. 합성 입력·모의 검증을 실제 GUI·게임·운영 확인으로 대신하지 않습니다. 질문한 뒤에도 답과 독립된 작업은 계속하며 같은 승인 확인을 반복하지 않습니다.

## 5. 기록과 종료

수행·자동 검증·미실행·완료 근거·대기/재개 조건을 소유 저장소의 기존 기록에 남깁니다. 지원 저장소에는 기존 ID와 결과를 연결하며 기능 상태를 중복 갱신하지 않습니다. 담당 변경만 검사·staging하고 게시·운영 적용은 현재 승인과 저장소 절차를 따릅니다.

기존 완료 조건을 실제로 충족한 항목만 완료 처리합니다. 문서 완료·정적 검사·기능 완료·게시 완료를 구분하고 빈 검사·일부 결과를 전체 완료로 확대하지 않습니다.

Goal의 완료·일시 중지·차단은 실제 도구의 조건으로만 변경합니다. 사용자 개입 대기·보류·예산 종료를 전체 목표 완료로 처리하지 않으며, 차단 상태의 반복 조건도 임의로 축약하지 않습니다. 더 이상 실행 가능한 승인 구간이 없으면 남은 원인·필요 결정·재개 조건과 현재 Goal 상태를 간결하게 보고합니다.

자동 감시·새 채팅·다른 채팅 메시지는 목표 실행의 기본값에 포함하지 않습니다.
