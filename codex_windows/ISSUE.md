# Codex Windows 확인된 문제와 제약

현재 직접 관찰과 아직 검증하지 않은 플랫폼 조건만 기록합니다. 구현 후 해결 판정은 [PLAN](PLAN.md)과 [TODO](TODO.md)의 관련 검사 근거를 따릅니다.

## 1. cp949 기본 실행의 Markdown 검사 실패

Python 3.14.8 기본 UTF-8 mode 0과 cp949 출력에서 대표 link·heading·style 검사 11회가 인코딩 오류로 실패했습니다. 오류 입력의 종료 1도 정상 오류 탐지 통과로 처리하지 않습니다. link·heading은 상태 이모지 출력에서 UnicodeEncodeError가 발생했습니다. style은 한국어 UTF-8 문서의 기본 읽기에서 cp949 디코딩 실패도 확인했습니다. 같은 입력을 `-X utf8`로 실행한 11회는 통과했습니다. 향후 코드의 명시적 UTF-8 읽기·쓰기·출력과 네이티브 호출을 함께 검증해야 합니다.

## 2. POSIX와 fcntl 의존

기존 Python flock 예시·파일 소유 보존·Bash 절차와 보완 회귀 검사는 POSIX 조건을 포함합니다. 이를 Windows 네이티브 기능이나 보장으로 간주하지 않습니다. 동봉 kiro-lock helper의 이번 기본 검사는 fcntl 예시와 별도입니다. Windows 전용 구현에서 필요한 대체 방법과 조건을 정한 뒤 검증합니다.

## 3. Windows 메타데이터와 동시 잠금 미검증

실제 ACL·소유·확장 메타데이터·네트워크 파일시스템·비협력 writer·동시 잠금 경쟁은 검증하지 않았습니다. 단일 프로세스 흐름의 helper 성공을 전체 보장으로 확대하지 않습니다.

필요한 보장과 실패·복구 조건을 먼저 정하고 별도 fixture로 확인합니다. 운영 파일이나 권한을 임의로 변경하지 않습니다.
