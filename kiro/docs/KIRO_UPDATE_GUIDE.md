# Kiro 업데이트 지침

## 1. 대상과 범위

기존 Kiro Agent·Skill을 사용하는 사람이 선택 자산을 갱신할 때 사용하는 지침입니다. 최초 적용은 [Kiro 최초 적용 지침](KIRO_SETUP_GUIDE.md), 공통 안전 절차는 [공통 업데이트 절차](../../agent-workflows/common/UPDATE_TODO.md)를 따릅니다.

공용 문서는 체크리스트 원본으로 유지합니다. 적용 결과와 미완료 작업은 별도 개인 작업 기록에 남기고, 저장소 개발 과제는 [루트 TODO](../../TODO.md)에서 관리합니다.

## 2. 변경 검토

- [ ] 설치된 버전과 새 원본 commit·파일 해시를 확인합니다.
- [ ] 사용자 runtime의 자체 수정과 원본 변경을 구분합니다.
- [ ] agent·skill·prompt·hook의 추가·수정·삭제와 권한·외부 통신 변경을 검토합니다.
- [ ] 공개 미러 목록을 설치 허용 목록으로 간주하지 않고 필요한 파일과 의존성을 선택합니다.
- [ ] 누락 참조는 오타·선택 의존성·필수 의존성으로 구분합니다. 파일이 없다는 이유로 보안 지침을 삭제하지 않습니다.
- [ ] 삭제·덮어쓰기·권한 변경은 영향과 복구 방법을 별도로 검토합니다.

## 3. 갱신과 검증

1. runtime 검색 밖 staging에 선택 파일만 준비하고 기존 버전과 비교합니다.
2. JSON·Markdown·관련 script 문법과 참조, 라이선스·비밀정보를 검사합니다.
3. 기존 runtime을 백업하고 선택 파일 단위 dry-run과 변경 내역을 확인합니다.
4. 승인된 범위만 적용합니다. docs/와 개발 TODO는 runtime으로 복사하지 않습니다.
5. 실제 agent·skill 로딩과 대표 작업을 시험합니다. 검사를 실행하지 못하면 그 범위를 명시합니다.
6. 실패 시 추가 적용을 중지하고 변경된 파일만 복구합니다. 사용자 후속 수정과 기존 백업은 보존합니다.

적용 기록에는 원본 commit·선택 파일·해시·검사 결과·백업·복구 결과를 남깁니다. 전체 runtime 덮어쓰기나 권한 오류의 자동 sudo 우회는 하지 않습니다.

## 4. 선택 유지보수

다음 항목은 일반 사용자 업데이트의 필수 절차가 아니라 별도 승인할 개선 작업입니다.

- [참고 문서 색인](../../_reference/INDEX.md)을 읽고 중복·충돌·오래된 지침을 검토합니다.
- 외부 skill은 원본·commit·라이선스·권한·외부 통신·유지보수 상태를 확인한 뒤 필요한 패턴만 제안합니다.
- footer나 통계 정리는 본문·frontmatter·저작권 및 출처 고지 보존 여부를 먼저 확인합니다.
- Agent의 역할·권한·resource 연결, Skill의 적용 조건·검증·복구를 검토합니다.
- 검토 결과를 자동 수정 승인으로 취급하지 않습니다. 보존 원본 kiro/ 변경은 별도 승인이 필요합니다.
- 실행 환경에 skill-review 검토 기능이 있으면 활용하되, 기능이 없거나 실행하지 못한 경우 수동 검토와 구분합니다.

## 5. 문서 검증

저장소 루트에서 실행하며 설치 결과의 동작 시험을 대신하지 않습니다.

```bash
sia-md-style-check kiro/docs/
sia-md-heading-check kiro/docs/
sia-md-link-check kiro/docs/
git diff --check
```
