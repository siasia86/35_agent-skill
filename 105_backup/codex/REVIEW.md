# Codex 개인 스킬 복제본 사용 의도 적합성 리뷰

검토일은 2026-10-01입니다. 사용자는 `kiro/`처럼 실제 스킬이 들어 있고 필요한 폴더를 복사하여 사용할 수 있는 Codex 개인 스킬 모음을 원했습니다. 현재 `codex/`가 이 목적에 맞는지, 구현의 잘된 점과 잘못된 점을 검토합니다.

**판정: 실제 복사 가능한 스킬 구현은 존재하지만, 디렉토리의 구성과 개인 규칙의 이식 결과는 사용자가 기대한 단순한 개인 스킬 모음에 충분히 맞지 않습니다.** 복사 가능성은 이번 격리 검사에서 확인했고, 사용 의도와의 불일치는 파일 구조·내용·안내 방식에서 확인했습니다.

이 문서는 리뷰 결과입니다. `codex/` 폐기·삭제·재구현, 개인 홈 설치, commit·push는 수행하지 않습니다.

## 1. 검토 기준과 범위

### 1.1 사용자가 밝힌 목적

- `kiro/`는 실제 사용하던 스킬을 복제해 둔 Kiro 스킬 모음입니다.
- `codex/`도 실제 스킬이 들어 있어 복사해서 사용할 수 있는 모음으로 만들려던 디렉토리입니다.
- 사용자는 Kiro에서 사용하던 개인 규칙과 작업 방식을 Codex에서 활용하려 합니다.
- 이번 요청은 폐기 예정인 `codex/`의 잘된 점과 잘못된 점을 기록하는 것입니다.

따라서 평가 기준은 개인 스킬의 내용 보존, 복사 단위의 완결성, 복사 위치의 명확성, 간단한 사용 절차입니다. 중앙 배포 계약이나 조직 운영 체계를 완성했는지가 주된 수용 기준은 아닙니다.

### 1.2 사실과 해석의 구분

파일의 존재·개수·내용과 이번 검사 결과는 확인된 사실입니다. 복잡한 구조가 사용성을 떨어뜨리고 개인 규칙의 축약이 이식 목적에 맞지 않는다는 판단은 현재 사용자가 밝힌 목적에 따른 리뷰입니다.

기존 문서에는 과거 중앙 governance 합의와 개인 스킬 정리 요청이 기록되어 있습니다. 이 리뷰는 그 기록을 근거 없이 무단 작업으로 단정하지 않습니다. 과거 요청의 전체 대화는 확인하지 않았으며, 현재 요청을 기준으로 최종 제공물의 적합성을 평가합니다.

## 2. 실제 상태와 판정

검토 기준 Git HEAD는 `4227f1d6b703238e3d2b763a0d320998cfeedc09`입니다. 아래 파일 개수는 이번 검토에서 실제 파일을 열거한 결과입니다.

| 대상                       | 확인 결과                      |
|----------------------------|--------------------------------|
| `kiro/`                    | 파일 55개, 스킬 진입점 19개    |
| `codex/`                   | 파일 131개                     |
| `codex/payload/`           | 파일 31개                      |
| `codex/payload/skills/`    | 스킬 16개, 동반 파일 포함 20개 |
| `codex/payload/agents/`    | 에이전트 TOML 10개             |
| `codex/archive/`           | 보존 파일 49개                 |
| `codex/`의 payload 외 영역 | 파일 100개                     |

파일 수 자체가 품질을 결정하지는 않습니다. 다만 개인 사용용 스킬보다 보존·개발·계약 문서가 훨씬 넓은 영역을 차지하고 있다는 구조적 사실을 보여 줍니다.

현재 수동 복사 단위는 `codex/payload/skills/<이름>/` 전체입니다. 개인 설치 위치는 기본적으로 `~/.agents/skills/<이름>/`입니다. `work-rules`의 참조 3개와 Python 템플릿의 asset 1개도 해당 폴더와 함께 복사해야 합니다. 개인 스킬 경로와 폴더 구조는 [OpenAI 공식 스킬 안내](https://learn.chatgpt.com/docs/build-skills)와 일치합니다.

이번 검사에서는 스킬 폴더만 임시 사용자 홈 구조에 복사했습니다. `codex/`의 catalog·prompts·policies와 다른 저장소를 복사하지 않고도 현재 스킬의 로컬 파일 참조가 유지됐습니다. **따라서 스킬이 없거나, 모두 외부 관리 시스템 없이는 사용할 수 없다는 평가는 사실과 맞지 않습니다.**

이 결과는 복사본의 정적 완결성입니다. 실제 Codex 세션에서의 자동 발견·호출·개인 작업 결과가 원래 Kiro와 같다는 의미는 아닙니다.

**후속 diff 확인: Kiro 원본과 파일 내용이 완전히 동일한 현행 스킬은 0개입니다.** 같은 이름의 11개는 모두 본문이 달라졌고, 나머지 5개는 Kiro에 같은 이름의 스킬이 없습니다. 16개가 복사 가능한 구조라는 평가와 원본 내용이 보존됐다는 평가는 구분해야 합니다. 전체 결과는 7.3절에 기록합니다.

## 3. 잘된 점

### 3.1 실제 스킬 파일과 독립 복사 단위를 만들었습니다

`codex/payload/skills/`에는 이름과 설명을 가진 `SKILL.md` 16개가 있습니다. 선언이나 설계 문서만 있는 폴더가 아닙니다. 수동 복사 후 20개 파일의 catalog 해시와 로컬 링크 4개를 확인했습니다.

`work-rules/references/`와 `python-script-template/assets/`가 스킬 내부에 있어, 필요한 동반 파일을 폴더 단위로 가져갈 수 있습니다. 이 구성은 재작성하더라도 유지할 가치가 있습니다.

이 항목의 긍정 평가는 파일 구성과 복사 단위에 한정합니다. Kiro 원본의 충실한 복제로 평가하지 않습니다. 후속 diff에서 같은 이름의 스킬 11개 모두 원문·본문 차이가 확인됐습니다.

### 3.2 Kiro 고유 호출과 환경 가정을 줄였습니다

현행 스킬은 Kiro의 `skill://` 리소스 로딩이나 Kiro 훅이 이미 동작한다고 가정하는 방식에서 벗어났습니다. 저장소 지침, 설치된 검사 도구, 실제 대상 경로를 확인하도록 변경한 점은 Codex 이식에 필요한 개선입니다.

예를 들어 Git 스킬은 오래된 고정 브랜치를 그대로 사용하지 않고 현재 브랜치와 저장소 규칙을 확인합니다. `repo-governance`는 `.governance/`가 없다는 이유로 새 정책을 자동 생성하지 않습니다. 원본의 `eval` 사용과 권한·프로세스 정리 예시를 그대로 실행하게 하지 않은 점도 적절합니다.

### 3.3 일부 개인 규칙을 구체적으로 유지했습니다

`git-commit-rule`에는 한국어 type-prefix 메시지, 제목 전체 50자 이내, 마지막 마침표 생략이 남아 있습니다. Python 스킬에는 안전 스위치, 날짜 기반 버전, `parse_args()`와 `main()` 같은 개인 골격이 남아 있습니다.

모든 개인 규칙이 사라진 것은 아닙니다. 유지된 규칙을 기준으로 원본 대응을 다시 정리할 수 있습니다.

### 3.4 독립 설치 도구와 기존 파일 보호가 구현되어 있습니다

`codex/scripts/setup_personal_skills.py`는 로컬 catalog와 Python 표준 라이브러리만으로 선택한 스킬을 설치합니다. 30·31 저장소나 네트워크를 필수로 요구하지 않습니다.

기존 파일이 같으면 건너뛰고, 다르면 덮어쓰기를 거부합니다. 누락된 동반 파일·해시 불일치·잘못된 경로·중복 선택을 검사하며, dry-run은 대상 폴더를 만들지 않습니다. 기존 격리 테스트 10개를 이번에 실행하여 통과했습니다.

단순 복사본에는 설치 도구가 필수는 아니지만, 이 도구의 구현 자체는 유효한 성과입니다.

### 3.5 원본과 검증 상태를 보존했습니다

Kiro/GPT 원본, 최초 manifest, archive가 남아 있어 비교와 복구가 가능합니다. 정적 검사, 설치, 발견, 모델 행동 검증을 구분한 기록도 적절합니다.

파일 복사 성공을 곧 모델 행동 검증 완료로 표시하지 않은 점은 유지해야 합니다. 다만 이러한 상태 구분을 개인 사용자에게 전달하는 방식에는 개선이 필요합니다.

## 4. 잘못된 점과 영향

P1은 현재 사용 목적을 크게 방해하는 문제, P2는 사용·유지보수 부담이나 검증의 미완성을 뜻합니다. 보안 취약점의 심각도 등급은 아닙니다.

### 4.1 P1 — 개인 사용용 최종본보다 개발·관리 공간이 전면에 있습니다

**근거:** `codex/README.md:7`은 GPT 원본을 복사한 개발용 배포본이라고 설명합니다. `codex/AGENTS.md:5`는 설치 대상을 PAYLOAD_MAP과 catalog로 선택하도록 합니다. `codex/INTEGRATION_CONTRACT.md:5`부터는 세 저장소의 중앙 소유권과 배포 체계를 다룹니다.

사용자가 원하는 결과는 개인 스킬 모음의 위치와 복사 방법을 바로 알 수 있는 디렉토리입니다. 현재는 payload·archive·policies·templates·catalog·여러 PLAN/TODO/검증 문서를 구별해야 최종 사용 파일을 찾을 수 있습니다.

중앙 관리 기능은 별도 목적에는 유효하지만, 개인 스킬 복제본의 주된 구성과 진입 안내로 삼으면 요청한 결과가 흐려집니다. 개인용 완결본을 먼저 제공하고 개발 이력과 중앙 배포 기능을 별도 영역으로 분리했어야 합니다.

### 4.2 P1 — 개인 템플릿을 일반 조언으로 축약한 부분이 있습니다

**근거:** Kiro의 `bash-script-template/SKILL.md`는 294줄이며 실제 함수·로깅·단계 처리 예시를 포함합니다. Codex의 같은 이름 스킬은 22줄이고 실제 코드 템플릿이나 asset이 없습니다. Kiro의 `run_msg_info` 계열 함수와 개인 로그 양식이 복사 가능한 코드로 제공되지 않습니다.

Python은 Kiro 389줄에서 Codex 진입점 58줄과 asset 53줄로 바뀌었습니다. 기본 구조는 보존했지만 asset은 일반적인 입력 파일·dry-run·콘솔 로깅 예시입니다. 원본의 `_setup_logger`·색상 함수·세부 입출력 패턴을 동일한 개인 템플릿으로 제공하는 구성은 아닙니다.

줄 수 감소 자체가 결함은 아닙니다. 문제는 같은 이름을 유지하면서 사용자가 기대하는 구체적인 개인 양식이 재현되는지 확인하지 않았다는 점입니다. `eval`이나 특정 로그 경로를 수정하는 것은 타당하지만, 안전한 함수 구현·설정 가능한 로그 위치·개인 출력 양식으로 대체했어야 합니다.

### 4.3 P1 — 기존 개인 워크플로의 동등성을 확인하기 전에 목록을 재구성했습니다

**근거:** Kiro 스킬 19개 중 현행 Codex payload와 같은 이름은 11개입니다. 아래 8개는 현행 설치 목록에 같은 이름의 진입점이 없습니다.

- `using-skills`
- `planning-and-breakdown`
- `incremental-change`
- `doubt-driven-infra`
- `shipping-checklist`
- `readme-template`
- `kiro-lock`
- `zircon-readme-policy`

Codex에는 `ansible-review`, `fact-check`, `git-release`, `markdown-review`, `security-audit` 5개가 추가되어 현재 16개가 됩니다. 따라서 19개를 같은 기능으로 일대일 변환한 결과가 아닙니다.

기존 `WORKFLOW_SKILL_PLAN.md:42` 이후에는 제외·통합 사유와 보존 위치가 기록되어 있습니다. 이 기록은 무단 삭제를 입증하지 않으며, 원본도 남아 있습니다. 그러나 “일반 작업은 모델이 처리한다”는 판단만으로 개인 체크리스트·양식·호출 습관까지 동등하게 보존됐다고 볼 수는 없습니다.

예를 들어 `readme-template`의 개인 기본 규칙은 저장소에 정책이 있을 때만 적용하는 문서 관례로 바뀌었고, 계획·점진적 변경 스킬은 짧은 인프라 지침이나 저장소 계획으로 통합되었습니다. 후속 사용에서 동일한 결과가 나오는지는 이번 검사로 확인되지 않습니다.

재작성 시에는 스킬별로 유지·호출 방식 변환·통합·범위 제한을 구분하고, 개인 규칙의 변경을 실제 예시 결과와 함께 검토해야 합니다. 원본 이름이나 개수의 기계적 보존보다 기능의 보존이 중요합니다.

### 4.4 P2 — 최초 적용 문서가 개인 복사를 완료하는 안내로 부족합니다

**근거:** `codex/docs/CODEX_SETUP_GUIDE.md:3`은 공통 TODO로 연결하고, 31행은 실제 target 경로를 별도로 확인하도록 하며, 46행은 클라이언트가 지원하는 방식으로 적용하도록 안내합니다. 이 문서 자체에는 현재 스킬의 복사 명령과 구체적인 개인 목적지가 없습니다.

루트 `README.md`의 5.1절에는 실제 수동 복사와 Python 설치 절차가 있으므로 설치 안내가 전혀 없는 것은 아닙니다. 문제는 Codex README가 먼저 연결하는 최초 적용 문서보다 사용 가능한 절차가 다른 진입점에 있다는 점입니다.

개인 사용의 첫 안내에서 원본 폴더, 사용자 목적지, 동반 파일, 기존 파일 처리, 확인 방법을 바로 보여 줬어야 합니다. 상세한 배포·승인·복구 체계는 해당 작업이 필요할 때 연결하는 편이 목적에 맞습니다.

### 4.5 P2 — 설치기 사용 시 개인 수정과 catalog 갱신이 결합됩니다

**근거:** `setup_personal_skills.py`의 `snapshot()`은 원본 폴더의 전체 파일 목록과 각 파일의 SHA-256을 catalog와 대조합니다.

이 방식은 변조·누락 검출에는 좋습니다. 다만 개인 사용자가 `SKILL.md`를 수정하거나 참고 파일을 추가하면 catalog도 함께 갱신해야 해당 설치기를 계속 사용할 수 있습니다. 개인 스킬 모음의 가벼운 수정·복사 흐름에는 추가 유지보수 부담입니다.

수동 복사에는 이 제약이 없습니다. 따라서 catalog 기반 설치기를 잘못된 구현으로 단정하기보다, 선택 도구로 분리하고 단순 복사를 기본 사용 경로로 제공하는 것이 적절합니다.

### 4.6 P2 — 원래 작업 결과의 보존을 보여 주는 수용 검증이 부족합니다

설치기 검사와 파일 해시는 스킬을 정확히 옮긴다는 것을 확인합니다. 그것만으로 Kiro에서 사용하던 Bash 출력 양식, Markdown 기본 규칙, 계획·복구 절차가 Codex에서도 기대한 결과를 만든다는 것을 확인하지는 못합니다.

현재 문서도 미검증 상태를 구분하고 있으므로 완료를 허위로 주장한 것으로 단정하지 않습니다. 다만 개인 복제본의 완성 여부를 판단하려면 복사·발견에 더해 대표 작업의 결과를 원래 개인 규칙과 대조해야 합니다.

공식 Astra 안내는 짧고 명확한 설명과 필요한 자료만 읽는 방식을 제안합니다. 이식할 개인 규칙을 특정 목록으로 삭제하라는 지시는 아닙니다. 경량화는 개인 규칙 보존과 함께 평가해야 합니다. [OpenAI 공식 Astra 안내](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)
