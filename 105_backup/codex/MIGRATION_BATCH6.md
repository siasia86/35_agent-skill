# Batch 6 asset migration record

## Scope and boundary

This development-only batch prepares static payload candidates from the 23 skills and 8 custom agents not included in the prior five retained payload assets. It changes only `codex/payload/`, [ASSET_CATALOG.json](ASSET_CATALOG.json), and [PAYLOAD_MAP.md](PAYLOAD_MAP.md). Original `gpt/`, `kiro/`, `codex/.agents/`, and `codex/.codex/` are preserved. No runtime installation, configuration activation, commit, push, release, or deployment occurred.

## Evidence reviewed

- Original skill entrypoints under `gpt/.agents/skills/`, all original agent TOML under `gpt/.codex/agents/`, and referenced `gpt/prompts/{ansible-review,fact-check,md-review}.md` were inspected before conversion.
- The original reference graph contains prompt entrypoints, cross-skill entrypoints, `policies/`, `markdown/STYLE.md`, Kiro hooks, private `/root/...` paths, fixed branch rules, and environment-specific tools. A folder-only payload would leave those references unresolved.
- The portable replacements retain meaningful outcomes: structured review, specification and planning gates, safety and authorization boundaries, validation, rollback, and clear reporting. They do not retain unconditional approval bypasses, personal paths, hook activation, memory management, model IDs, MCP configuration, remote commands, or deployment authority.
- Official OpenAI documentation confirms that a skill requires a `SKILL.md` with `name` and `description`, and that custom-agent TOML requires `name`, `description`, and `developer_instructions`. See [Build skills](https://learn.chatgpt.com/docs/build-skills) and [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents).

## Conversion decisions

- Prompt/cross-skill entrypoints no longer depend on out-of-folder instructions; distinct scopes and unavailable checks are retained.
- `kiro-lock` preserves only the manual coordination intent as a static candidate. Its automatic pre-tool hook, disabled marker, hook lifecycle, and race/interrupt behavior have **no confirmed Codex equivalent and are explicitly deferred**. No claim of automatic concurrent-edit protection is made.
- Path, branch, badge, scanner, and project-specific rules are conditional on actual repository guidance.
- Script and infrastructure skills retain error handling, testing, idempotency, rollback, and least-privilege intent without service, host, SSH-key, sudo, or private tooling dependencies.
- Review/advisory agents are `read-only`; implementation agents use `workspace-write` only for requested implementation. All inherit model choice and have no MCP dependency or model hardcoding.
