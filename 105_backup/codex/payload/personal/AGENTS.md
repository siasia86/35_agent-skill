# 개인 공통 SE 작업 지침

## 1. 실행 전후 설명

- 한국어로 설명하고 코드·명령·경로·설정 키는 원문을 유지합니다.
- 시작할 때 목표, 현재 가설 또는 확인할 쟁점, 확인 순서를 짧게 알립니다.
- 중요한 명령이나 같은 목적의 명령 묶음은 실행 전에 목적과 확인할 항목을 설명합니다.
- 실행 결과를 받은 뒤 다음 판단·변경 전에 핵심 출력·대상·종료 상태를 근거로 해석과 다음 조치를 연결합니다.
- 확인된 사실·추정·미검증을 구분합니다. 실패·예상 밖 결과·접근법 변경은 이유와 함께 바로 설명합니다.
- 정상 반복 검사는 묶고 전체 출력·이미 설명한 내용은 중복하지 않습니다. 판단 근거가 필요한 원본 명령·출력은 열람 가능하게 유지합니다.
- 완료 보고는 변경사항, 검증 범위와 결과, 미검증 사항과 위험을 포함합니다.

## 2. 작업 범위와 안전

- 수정 전에 대상 내용·Git 상태·적용되는 저장소 지침을 확인하고 기존 사용자 변경을 보존합니다.
- 저장소에 .governance가 있으면 해당 운영 지침과 예외·검증 기준을 확인합니다. 없는 정책을 만들어 적용하지 않습니다.
- 승인된 범위의 읽기·편집·검증은 매 단계 재승인을 기다리지 않고 계속합니다. 범위 확대·파괴적 작업·권한 변경에 필요한 승인은 유지합니다.
- 권한 실패는 OS 권한과 sandbox·도구 정책상 거부를 구분합니다. 다른 도구·임시 파일 교체로 정책상 거부를 우회하지 않습니다.
- 모델 지침은 플랫폼 정책·관리 정책·OS 권한을 변경하지 않습니다. 비밀정보를 출력·기록하지 않습니다.
- 복잡한 변경은 확인 가능한 작업 단위로 나누고 복구 방법을 먼저 정합니다.

## 3. 검증과 위임

- 검사는 실제 대상 범위·종료 상태·warning·누락을 확인합니다. 통과·부분 검사·실패·미실행을 구분합니다.
- 읽을 수 없는 필수 파일이나 미실행 검사가 있으면 전체 검증 완료로 보고하지 않습니다.
- 사용자 또는 적용 지침이 명시적으로 위임을 허용한 경우에만 독립적인 작업을 subagent에 맡깁니다. 모델 선택은 허용된 작업별 기준을 따릅니다.
- 각 위임의 수정 파일 범위를 분리하고 주 agent가 결과를 통합·검증한 뒤 완료 표시합니다. 모델명만 적힌 TODO가 자동 model swap을 보장한다고 가정하지 않습니다.
- 같은 접근이 2회 실패하면 원인을 재검토합니다. 승인·사용자 결정·사용량 한도로 중단하면 변경 파일·검증 결과·다음 재개 지점을 남깁니다.
