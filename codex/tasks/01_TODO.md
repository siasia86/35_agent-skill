# 지침·skill 경량화 효과 비교

- 작업: 01, 상태: 예정.
- 목표: 지침·설명·skill 경량화의 품질과 전체 사용량 영향을 비교합니다.
- 범위: 승인된 격리 작업과 실제 제공되는 사용량만 측정합니다.
- 완료 조건: 비교 조건·원본 결과·품질·검증 누락·사용량과 한계를 기록합니다.
- 선행 조건: 사용할 모델·도구·격리 대상·측정 가능 항목을 확정합니다. 번호 등록은 실행 승인이 아닙니다.

## 1. 비교 기준

판단: 지침과 설명은 추가 입력·출력을 만들고, 이후 요청에 포함되는 설명 이력도 입력량에 영향을 줍니다. 그러나 실행 경로·재시도까지 달라질 수 있어 작업 전체 사용량이 항상 일정 비율로 증가한다고 단정할 수 없습니다. 아직 동일 조건의 적용 전후 실행을 측정하지 않았으므로 **실제 증가율은 미확인**입니다.

공식 API 사용량에서 `cached_tokens`는 입력의 부분집합이고 `reasoning_tokens`는 출력의 부분집합입니다. 합계에 중복 가산하지 않습니다. 입력·출력·캐시의 과금 차이 때문에 전체 토큰 증가율과 비용 증가율도 같지 않습니다. 이 계측 원칙을 Codex에 적용할 때는 해당 실행 환경이 제공하는 사용량 필드를 확인해야 합니다. [Observability and usage](https://developers.openai.com/api/docs/guides/agents-api/observability)

계산 예시일 뿐 실측치는 아닙니다. 작업 전체의 추가 사용량이 이력 재입력을 포함해 1,000토큰이라고 가정하면, 기존 총량 5,000토큰 대비 20%, 50,000토큰 대비 2%입니다. 제안 문안 자체가 1,000토큰이라는 뜻은 아닙니다. 짧은 작업에는 설명 비중이 클 수 있으므로 매 명령의 반복 해설보다 중요한 판단 단위의 요약을 우선합니다.

## 2. 남은 작업

- [ ] 동일 모델·추론 노력·요약 설정·도구·저장소 snapshot·초기 대화 조건에서 A(추가 지침 없음)와 B(루트 TODO의 5.2절 적용)를 비교합니다. 플랫폼 기본 진행 설명은 A에서도 유지합니다.
- [ ] 단순 문서 수정, 코드 변경·테스트, 장애 진단을 각각 독립 세션에서 여러 번 실행하고 캐시 조건·실행 순서를 기록합니다.
- [ ] 작업 전체의 호출별 입력·캐시 입력·출력·추론 토큰, 호출 수·재시도·소요 시간과 결과 품질을 수집합니다. 누적값은 차분하고 subagent 중복 집계를 피합니다.
- [ ] `(B 전체 토큰 - A 전체 토큰) / A 전체 토큰 × 100`과 절대 차이·중앙값·범위를 함께 보고합니다. 설명 문자열의 토큰 수만으로 전체 증가율을 대신하지 않습니다.
- [ ] 추가 검사가 생긴 경우 설명량 증가와 작업 범위 증가를 구분합니다. 요약 상세도 비교는 지침을 고정한 별도 시험으로 수행합니다.
- [ ] 재현성·검증 누락·추가 질문 감소도 평가하여 허용 증가량을 정합니다. 구독 사용 한도와 API 토큰·비용을 같은 비율로 환산하지 않습니다.

- [ ] skill 경량화 전후를 같은 필수 정책 아래 별도 비교합니다. 단순 문서 수정·선택한 개인 Python 양식·인프라 계획에서 관련 참조만 읽는지, 불필요한 재승인·검증 누락·조기 종료가 생기는지 기록합니다.
