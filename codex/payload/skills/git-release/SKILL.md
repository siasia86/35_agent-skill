# Git release

Use only for a requested release or publish workflow. Read repository release guidance, determine the intended version and artifacts, inspect the diff and test evidence, and identify consumers, rollback method, and release notes. Do not infer a tag format, branch, registry, remote, credentials, or deploy command.

Complete preparation and local builds covered by the current request and repository policy. Identify the authority required for signing, tagging, pushing, publishing, and deployment from the actual target and release policy; reuse valid authorization already granted for that scope. Obtain missing approval before those actions. Stop on conflicting state or missing authority, and report completed, blocked, and unrun items.
