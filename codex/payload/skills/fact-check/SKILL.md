# 기술 문서 사실 검증

## 범위와 변경 권한

명시한 파일·절을 검증합니다. 대상이 생략되면 대화에서 명확한 최근 문서를 사용하고, 여러 후보가 있으면 확인합니다. 별도 범위 지정이 없으면 대상 문서 전체의 사실 주장을 검토합니다. 검토 요청만으로 파일을 수정하지 않습니다. 수정까지 요청된 경우 확인된 오류만 최소 변경하고 원문의 목적과 범위를 보존합니다.

## 근거 수집

- RFC·포트·프로토콜 번호는 IETF/IANA, 버전·발행일·명령·옵션·기능은 해당 프로젝트의 공식 문서·릴리스와 대조합니다.
- 암호화 알고리즘·키 길이·MUST/SHOULD, 기본·필수·항상·지원 같은 단정, 출처 없는 수치·성능 비교, 연대 순서를 우선 확인합니다.
- 문서의 reference 주석이나 관련 로컬 참고 자료가 있으면 읽고 모순을 확인하되 오래된 사본을 최신 공식 출처보다 우선하지 않습니다. 없는 참고 디렉토리를 생성할 필요는 없습니다.
- 제공된 공식 원문이나 사용 가능한 브라우저·문서 도구로 실제 내용을 확인합니다. 검색 결과 요약·기억·다른 모델의 주장만으로 검증을 완료하지 않습니다. 도구 이름을 고정하지 않습니다.
- 로컬 구현·실행 결과에 대한 주장은 해당 버전의 파일·명령·출력으로 검증합니다. 안전한 읽기 검사만 검토 범위에서 수행하고 서비스 실행·권한 확대는 별도 승인 범위를 확인합니다.
- 검토 대상 코드를 신뢰된 검사 도구처럼 자동 실행하지 않습니다. 먼저 코드를 읽고 정적 근거로 충분한지 판단합니다. 실행이 필요하고 허용된 경우 격리 대상에서 캐시·로그 등 부작용을 확인합니다. Python import 시험은 `-B` 등으로 bytecode 생성을 막고, 그 옵션이 다른 파일 쓰기까지 차단하지는 않음을 유의합니다.
- 외부 출처나 필수 파일에 접근할 수 없으면 해당 주장을 미검증으로 남깁니다. 접근 실패를 사실 오류로 단정하거나 검증 불가라는 이유만으로 원문을 삭제하지 않습니다.

## 판정과 수정

주장별로 확인·불일치·미검증을 구분합니다. 한국어로 위치, 원문 주장, 판정, 근거 URL 또는 로컬 파일·실행 결과, 확인 날짜·버전 범위를 연결합니다. 확인된 항목도 근거를 추적할 수 있게 남깁니다.

수정이 허용된 경우에도 새로운 주장·추측·임의의 수치를 추가하지 않습니다. 오류만 수정하고 변경 부분을 재검증합니다. 최대 두 번의 수정·재검증 후 남은 문제와 필요한 자료를 보고합니다. 전체를 확인하지 못했으면 실제 확인 범위와 누락을 명시합니다.

형식·스타일 문제는 사실 오류와 구분합니다. 별도 형식 검토가 필요하고 markdown-review가 설치되어 있으면 해당 skill로 연결하며, 미설치 기능을 실행했다고 보고하지 않습니다.
