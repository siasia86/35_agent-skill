## 4. 설치와 활성화 분리

진행 상태는 차이 확인 → staging 설치 → 사전 검증 → runtime 활성화 → 실행 검증으로 구분합니다. 아래 상태명은 제안이며 현재 30의 command 이름이 아닙니다.

- 차이 확인: 명세·버전·의존성·대상 안전성·권한·충돌을 판정하며 대상은 변경하지 않습니다.
- staging 설치: runtime이 검색하지 않는 위치에 선택 파일을 준비하고 해시·파일 집합을 검사합니다.
- 사전 검증: 문법·참조·검사 도구·격리 시험·권한 조건을 확인합니다. 필수 검증 누락이나 부분 검사는 활성화 조건을 충족하지 않습니다.
- 활성화: 승인된 파일을 runtime 검색 경로에 배치하거나 hook을 연결합니다. 파일 복사가 곧 자동 발견을 허용하는 경우 이 최종 배치가 활성화입니다.
- 실행 검증: 실제 발견·위임·hook 실패 전달 등을 확인합니다. 실패하면 추가 활성화를 중단하고 승인된 비활성화·복구 절차를 수행합니다.

별도 enable 명령이 없는 자산에 가상의 비활성 설치 상태를 약속하지 않습니다. hook이 없는 profile은 hook 등록을 해당 없음으로 표시하되 필요한 자산 발견·동작 시험은 유지합니다. 여러 파일 배포를 파일 하나의 atomic 교체로 보장한다고 주장하지 않습니다.

활성화는 검증된 staging artifact·계획 ID와 파일 집합 aggregate hash에 결합해야 합니다. 최종 실행 전 재검증하고 검증 후 mutable 원본을 다시 복사하지 않습니다. 이 조건은 후속 활성화 구현 요구사항이며 현재 계획 검증기의 지원 기능이 아닙니다.
