# Shipping checklist

Use for a requested release or deployment. Confirm code review and validation evidence, expected change set, environment target, secret handling, least privilege, backup/state protection, rollback trigger and owner, health checks, monitoring, notification, and stakeholder requirements. Match the project’s release process instead of assuming a cloud, health endpoint, or rollout percentage.

Separate readiness review from the actual deploy. For live deployment, tag/publish, infrastructure apply, and rollback, verify authorization for the actual target and action; reuse valid authorization already granted and request only what is missing. Record completed, failed, skipped, and blocked checklist items; after an authorized release, verify observable behavior and monitor according to the agreed window.
