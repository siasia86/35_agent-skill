# 개인 skill 호출과 업데이트 보관

## 1. 세 위치의 역할

| 위치                            | 역할                             |
|---------------------------------|----------------------------------|
| `_reference/skills/<이름>/`     | 출처·비교·호출 연결              |
| `codex_windows/skills/<이름>/`  | 검증하는 Windows 관리·배포 원본  |
| 사용자 `.agents/skills/<이름>/` | 실제 개인 실행본; 폴더 전체 적용 |

[참고 색인](../../../_reference/INDEX.md)과 [Windows 설치 안내](../../../codex_windows/README.md)를 필요한 범위만 읽습니다.

## 2. 호출 예시

계획만 작성할 때:

```text
$planning-and-breakdown
현재 repo의 큰 작업을 의존성 순서로 분해하고 완료 조건·검증·복구를 정리해줘.
사용자가 지정한 기존 관리·업데이트 기록 폴더에 계획을 정리하고 이번에는 구현하지 마.
```

검증한 변경을 게시할 때:

```text
$git-commit-rule
이번 작업 파일만 검증·staging하고 한국어 설명·50자 이내 커밋으로 게시해줘.
현재 repo의 지정 branch와 사용자 검증 순서를 따라줘.
```

35에서는 yunli → 사용자 검증 → main 순서입니다. 이를 다른 repo의 강제 branch로 적용하지 않습니다. 설치된 이름·경로를 확인하고 보이지 않으면 지정한 SKILL 원본을 읽어 적용하도록 요청합니다.

## 3. 업데이트 폴더

개인 Codex 업데이트마다 35의 `agent-workflows/codex/<날짜>-<목적>-<작업ID>/` 하나에 before·after 전체 skill 사본, inventory·검증·복구를 묶습니다. 다음 업데이트는 새 이름으로 추가합니다. 실제 AGENTS·config와 raw는 그 폴더의 private/에 보관하고 Git 제외를 확인합니다.

이전 사본은 조회·복구 자료이며 현재 설치 입력으로 자동 사용하지 않습니다. 설치·발견·선택·대표 행동은 각각 실제 관찰 범위를 기록합니다.
