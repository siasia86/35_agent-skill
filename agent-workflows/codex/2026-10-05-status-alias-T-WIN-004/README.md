# 짧은 상황보고 호출문 개인 지침 반영

## 1. 요청과 범위

T-WIN-004 후속으로 `$상황보고`와 `@상황보고`를 같은 개인 보고 요청으로 연결했습니다. [개인 AGENTS 원본](../../../codex_windows/AGENTS.md), [work-rules](../../../codex_windows/skills/work-rules/SKILL.md), [상황보고 상세 기준](../../../codex_windows/skills/work-rules/references/STYLE.md#상황보고-호출문)이 담당 범위입니다. 앞선 [4열 표 갱신](../2026-10-05-status-usercheck-table-T-WIN-004/README.md)의 기능 상태·승인·보류 경계를 유지합니다.

## 2. 결과와 적용

| 대상·담당          | 확인된 결과                                                                    | 남은 조건                                             | 사용자 확인용 `.md` |
|--------------------|--------------------------------------------------------------------------------|-------------------------------------------------------|---------------------|
| 개인 AGENTS        | 두 짧은 호출문과 work-rules 참조를 연결하고 공통 본문을 홈에 병합              | 기존 다른 채팅의 최신 지침 수신·실제 호출 행동 미확인 | 사용자 확인 없음    |
| Windows work-rules | 같은 4열 표와 실제 사용자 행동 안내 연결, 전체 44파일 보존·지정 설치·해시 일치 | 독립 채팅의 실제 발견·선택·행동 미확인                | 사용자 확인 없음    |

호출문은 현재 요청한 담당 범위의 상황 보고입니다. 최신 소유 원본과 직접 근거를 필요한 범위만 읽기 전용으로 확인합니다. 마지막 열은 실제 확인·시험·입력·선택 안내이며 TODO·PLAN이나 단순 결과 원본으로 대신하지 않습니다. 안내 준비 중·확인 없음·보류를 구분하고 완료된 확인을 다시 요청하지 않습니다.

한국어 표기를 앱 명령·skill 자동완성 대상으로 등록하지 않았습니다. 실제 skill 이름은 `work-rules`로 유지합니다. 호출 자체로 새 Goal·기능 실행·게시·메시지·자동 감시를 추가하지 않으며 이미 승인된 작업을 새 승인 대기로 바꾸지 않습니다.

## 3. 검증과 보존

- 변경 전 skill 전체 44파일과 AGENTS 원본·홈 사본·해시를 Git 제외 private에 보존했습니다.
- 기존 홈의 로컬 관리 원본 경로 안내는 보존했습니다. 공개 원본에는 개인 절대 경로를 복사하지 않고 공통 본문만 병합했으므로 홈 전체 해시와 공개 원본 해시의 차이는 의도된 로컬 추가 구간입니다.
- 공식 skill 형식, 변경 문서 헤딩·파일 링크와 교차 앵커를 검사했습니다. 표현 검사의 기존 진단과 추가 진단을 [검증 기록](validation.json)에서 구분합니다.
- 설치한 skill 전체 파일 목록·해시 일치와 AGENTS 공통 본문·로컬 추가 구간 보존을 확인했습니다. 다른 채팅에 지침을 보냈거나 기존 채팅이 즉시 갱신됐다고 보고하지 않습니다.

## 4. 복구와 후속 확인

이번 이전본과 현재 사용자 변경을 먼저 대조합니다. 필요할 때 이번 변경한 공통 규칙만 복구하고 로컬 추가 구간·다른 skill·설정은 보존합니다. 게시 후 복구는 검토한 revert로 진행합니다. 다음 실제 사용자 호출에서 행동을 확인하며 별도 시험용 채팅·Goal·자동화를 만들지 않습니다. 게시 commit·원격 SHA는 Git 기록과 최종 보고에 연결합니다.
