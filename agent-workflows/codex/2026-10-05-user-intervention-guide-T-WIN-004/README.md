# 사용자 확인·개입 안내 가시성

## 1. 반영 기준

T-WIN-004 후속으로 사용자 확인·개입 안내의 담당·현재 상태·사용자가 할 일·직접 근거·최소 확인 절차·회신 항목·재개 행동을 이모지와 표/목록으로 구분합니다. 이모지는 가시성을 높이는 표현 수단이며 승인·권한·보류·선행 조건·완료 판정에 영향을 주지 않습니다. 실제 판정은 최신 사용자 지시·소유 PLAN/TODO·검증 근거를 따릅니다.

개인 [AGENTS](../../../codex_windows/AGENTS.md), [work-rules](../../../codex_windows/skills/work-rules/SKILL.md), [안내 본문](../../../codex_windows/skills/work-rules/references/STYLE.md#사용자-확인개입-안내)과 현행 STYLE 사본 7개를 반영합니다. 자동 검증 우선·기존 보류 유지·사용자 답과 독립된 작업 계속·실제 PNG/파일 준비·공개 범위와 상태 원본을 유지합니다. 새 skill이나 앱 알림 표시 변경은 추가하지 않습니다.

## 2. 보존·검증·설치

이전 갱신과 분리한 private/before에 source 폴더 전체·기존 설치 폴더 3개·개인 AGENTS와 파일 해시를 보존했습니다. 실제 내용 차이는 없었고 기존 캐시·개인 경로 부록은 유지했습니다. 검증 후 기존 work-rules·git-commit-rule·md-link-check의 전체 배포 폴더와 개인 AGENTS의 지정 문구만 반영했습니다. 내용 파일 80개의 집합·해시 일치와 개인 AGENTS의 지정 문구 외 보존을 확인하고 private/after에 설치 결과를 보존했습니다.

문서·skill 구조·동일 사본·source/installed 파일 집합 및 해시 검사는 [집계](validation.json)에 기록합니다. 검사기 코드는 변경하지 않았으므로 이전 보라색의 462회·198회 회귀를 반복하지 않습니다. 기존 STYLE 진단과 이번 추가 진단을 구분하고 의미 대조는 승인·원본·자동 검증·미확인 경계를 확인합니다.

## 3. 복구·남은 범위

복구 전에 이후 사용자 변경을 대조하여 이번 변경만 private/before의 이전본으로 선택 복원합니다. 게시 후 원본 복구는 검토한 revert를 사용합니다. 실제 홈·원형 백업·개인 경로·raw는 공개 문서에 복사하지 않습니다.

지정 설치와 문서 검사를 독립 새 세션의 장기 행동 검증으로 확대하지 않습니다. 해당 미확인 범위는 기존 Windows TODO의 T-WIN-004에 유지합니다. 추가 사용자 테스트·새 Goal·채팅·자동 감시·앱 테마·config·기능 구현은 수행하지 않았습니다. 게시 결과는 기존 단일 Git 통합 담당이 확인합니다.
