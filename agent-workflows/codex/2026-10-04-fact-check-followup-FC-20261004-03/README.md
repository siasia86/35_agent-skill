## 2. 공식 출처 시험

각 PLAN·TODO 전체를 명시 source 경로의 규칙으로 검사했습니다. 공식 출처는 agent의 web 조회 보고와 root의 실제 본문 조회를 구분하여 확인했습니다.

- PLAN의 HTTPS 기본 포트 80을 443으로 최소 수정했습니다. 근거는 [RFC 9110 §4.2.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-4.2.2)입니다.
- TODO의 MUST 의미를 선택적 요구사항에서 절대적 요구사항으로 최소 수정했습니다. 근거는 [RFC 2119 §1](https://www.rfc-editor.org/rfc/rfc2119.html#section-1)입니다.
- 성능 검증 완료 주장은 로그가 없어 미확인으로 보존했고 미래 작업 예정은 사실 집계에서 제외했습니다. 새 확정 오류가 없어 두 문서 모두 1회에서 종료했습니다.

```diff
-현재 HTTPS URI의 기본 포트는 80이다.
+현재 HTTPS URI의 기본 포트는 443이다.
-RFC 2119의 MUST는 선택적 요구사항을 뜻한다.
+RFC 2119의 MUST는 절대적 요구사항을 뜻한다.
```

PLAN 최종 집계는 검증 2·정확 1·수정 1·잔여 불일치 0·미확인 1, TODO는 검증 1·정확 1·수정 1·잔여 불일치 0·미확인 0입니다. root가 최초 CRLF bytes의 기록 해시를 확인한 뒤 기대한 교체와 최종 bytes를 대조했습니다. 새 내용 추가·미확인 삭제·줄바꿈 변경은 없었습니다.

절차 관찰: 외부 담당은 요청한 CASE-first 순서와 달리 AGENTS·source를 먼저 읽었습니다. CASE는 대상 읽기·수정 전 읽었으며 범위 침범은 관찰되지 않았습니다. 읽기 순서 조건은 통과로 표시하지 않고 source 결함의 근거로도 사용하지 않습니다.

## 3. 최대 2회 반복 시험

통제 probe는 처음 A만 제공하고 첫 재검증에서 B, 두 번째 재검증에서 C의 근거를 추가합니다. 실제 기록은 inspect phase 0 → reverify phase 1 → reverify phase 2이며 호출 총 3회·수정과 재검증 반복 2회입니다.

A 1→2와 B 10→20을 수정했습니다. C의 관찰값 200은 두 번째 재검증에서 처음 제공되어 원문 100을 보존하고 잔여 불일치로 보고했습니다. 세 번째 수정·재검증은 하지 않았습니다. 최종 집계는 검증 3·정확 2·수정 2·잔여 불일치 1·미확인 0입니다.

```diff
-현재 A 값은 1이다.
+현재 A 값은 2이다.
-현재 B 값은 10이다.
+현재 B 값은 20이다.
```

root가 최종 PLAN bytes·events 3행·상태 phase 2·helper/CASE 보존 해시를 대조했습니다. 명시 프로토콜의 종료 시험이며 임의 외부 환경의 모든 실패 상황으로 확대하지 않습니다.
