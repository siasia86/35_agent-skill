# MAIN-20261004-01 스킬·인계·목록 main 병합

## 1. 요청과 범위

사용자가 현재까지의 작업을 main까지 병합하고, 모순이나 의도 불일치가 확인되면 중단하도록 요청했습니다. `mian`은 문맥상 `main`으로 해석했습니다. 이번 작업은 35의 LC-PUB·UA-MIN·FC 생성/보완, 02의 fact-check 인계, 32의 스킬 목록 변경에 한정합니다. 게임 저장소나 운영 자료는 대상에 포함하지 않습니다.

주 검토·최종 판단·35/32 게시 담당은 Codex `/root`입니다. `/root/luna_premerge_docs`에는 `gpt-6-luna`를 지정하여 02·32의 전체 변경을 읽기 전용 검토하도록 했습니다. 모델 표기는 위임 요청의 관찰이며 독립 런타임 조회를 뜻하지 않습니다.

## 2. 실제 병합과 동시 작업

35의 main `2632fe1`에서 [8bb4c83](https://github.com/siasia86/35_agent-skill/commit/8bb4c83932b0b25f6a0192ed64ad4549e6813ba7)까지 4개 커밋을 fast-forward하고 일반 push했습니다. 원격 main이 같은 전체 SHA인지 확인했고 작업본은 yunli로 돌아왔습니다.

02는 검토 시작 당시 main `f280cc1`, yunli `41086f4`였으나 검토 중 다른 작업에서 main이 이미 fast-forward되었습니다. 원격 main·yunli가 모두 [41086f4](https://github.com/siasia86/02_zircon-workspace-plan/commit/41086f4558a0aa8f22318d5ccca9586e54e285d5)임을 확인했습니다. 이번 담당은 02를 중복 병합하거나 기록 파일을 수정하지 않았으며 최초 기준부터의 2개 커밋을 별도로 검사했습니다.

32는 main `4ead671`에서 스킬 목록의 [faa6574](https://github.com/siasia86/system-engineering-resources/commit/faa6574e8d80ec90ee02f32091d9a939b225575a)까지 조상 관계와 예상 이전 SHA를 확인한 뒤 local main을 fast-forward하고 일반 push했습니다. checkout을 유지하고 원격 SHA와 파일 해시를 대조했습니다.

이 절의 SHA는 기능 변경 병합을 관찰한 시점의 값입니다. 이번 완료 기록의 후속 commit·일반 push 결과는 Git 이력과 비공개 게시 receipt, 최종 사용자 보고에서 확인하며 기능 변경 커밋을 기록 커밋으로 덮어쓰지 않습니다.

## 3. 검토와 검증

확인된 모순·의도 불일치는 없었습니다. 각 문서의 사실 검증, 기본 최소 수정, 수정 금지·추론 금지·새 내용 추가 금지, 최대 2회와 결과 집계, 35 구현 원본/02 인계 지원의 역할, 로컬 설치 보류가 일치합니다. 과거 작업의 main 미실행 기록과 이번 명시적 병합 승인을 구분했습니다. 32의 스킬 31개는 작성 세션의 스냅샷으로 유지합니다.

병합 후보 변경 Markdown은 35에서 15개·02에서 8개·32에서 5개, 총 28개입니다. 표현·헤딩·파일 링크 445개, 교차 앵커 25개와 diff 공백·담당 파일/patch의 Gitleaks를 확인했습니다. 02의 교차 앵커는 해당 없음 0개이며 통과 범위로 부풀리지 않습니다. 35 메타데이터 3개·변경 JSON 4개, 02 JSON 1개와 32 root README inventory도 확인했습니다. [후보 검증 요약](validation.json)을 따릅니다.

35/02는 설치된 md-link-check의 26.10.03 도구를, 32는 기존 CAT 증거의 해시 8개를 대조한 sia_scripts v0.3.3을 사용했습니다. 35의 기존 배포 AGENTS·두 스킬은 기존 푸터 없는 양식만 유지했습니다. 32의 기존 TOML 예외는 변경하지 않았습니다.

## 4. 실패·원인·복구

첫 비공개 로그 경로는 Git 제외 규칙과 맞지 않아 생성 전 검사에서 멈췄습니다. 기존 `agent-workflows/codex/<작업>/private/` 규칙에 맞는 별도 경로로 옮겼으며 Git 제외 설정을 수정하지 않았습니다. 02의 이미 진행된 병합으로 동적 비교 범위가 0개가 되었을 때도 완료로 처리하지 않고 최초 기준 커밋부터 검사했습니다.

35 checkout 전후의 파일 보존 검사에서 9개 파일의 줄바꿈 차이가 발견되어 다음 저장소 병합을 중단하고 원인을 확인했습니다. 실제 core.autocrlf와 기존 attributes를 대조했고, 정규화한 내용은 모두 같았습니다. 관찰 파일을 보존한 뒤 검증한 이전 사본의 바이트로 복원했습니다. 원래 추적 파일 전체 해시와 index의 경로·mode·blob 일치를 확인했고 담당 9개만 index를 갱신하여 staged 변경 0개·clean을 확인했습니다. index stat-cache 바이트 동일성은 내용 보존과 구분합니다. 이후 32와 후속 기록 병합은 checkout을 변경하지 않는 조상 확인·이전 SHA 대조 방식으로 수행합니다.

## 5. 보류와 복구 기준

fact-check 로컬 설치는 사용자 요청대로 보류하며 두 사용자 스킬 위치에 신규 폴더가 없음을 확인했습니다. 새 세션 발견·암묵 선택·실제 후속 행동, 외부 사실 조회 시험·반복 상한 소진 사례, 수신 에이전트 acceptance, 원격 CI는 이번 병합으로 완료 처리하지 않습니다. 기존 Windows TODO와 02의 FCH-01 대기를 유지합니다.

복구가 필요하면 현재 변경과 병합 전 refs·index·해시·사본을 대조하고 검토된 revert를 사용합니다. force push·release·운영 적용·개인 설정 변경은 수행하지 않습니다. 전체 이전 파일·원형 경로·로그·게시 receipt는 Git 제외 증거에 보존합니다.
