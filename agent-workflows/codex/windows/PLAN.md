# Codex Windows 이관 계획

최초 기준 작업은 Linux의 **19개 skill과 확인된 설정 전체의 Windows 이관**입니다. 원문을 축약·삭제·통합하지 않습니다. 이후 사용자 요청의 추가·갱신은 아래 별도 작업 항목으로 구분합니다. 최초 이관의 기준과 증거는 [이관 기록](../WINDOWS_MIGRATION_2026-10-03.md)에 두고 현재 상태는 [TODO](TODO.md)에 연결합니다.

최초 이관과 LC-PUB의 당시 게시 순서는 역사 자료입니다. 현행 일반 작업은 아래 BRANCH-POLICY의 main 기본 절차를 따르며 과거 사용자 검증 대기를 반복하지 않습니다.

## 1. 전체 원본과 설정 확인

19개 이름·182개 파일·동봉 역할 54개·Python 도구 25개와 개인 공통 지침·저장소 config를 출처 manifest로 대응합니다. 활성 설정과 폐기한 `105_backup`의 agent/payload 예시를 구분합니다. 실제 개인 홈의 인증·MCP·모델 설정은 공개 자료에 복사하지 않습니다.

## 2. Windows 본문과 필요 도구 이관

각 skill의 전체 규약을 보존하고 Windows 호환 절·PowerShell/Python 실행 절차·로컬 참조·필요 도구를 작성합니다. Bash 역할은 Git Bash/WSL로 유지합니다. 플랫폼 차이와 기존 재현 결함은 최소 호환 수정으로 해결합니다. 모든 기존 파일을 보존 경로와 SHA-256으로 대조합니다.

## 3. 최초 이관의 검증과 yunli 게시

메타데이터·원본 보존·단독 복사·UTF-8·정상/실패 입력·Markdown 문법·원자 쓰기·잠금 경쟁을 TEMP fixture에서 확인합니다. 실제 검사와 미실행 범위를 구분해 기록하고 yunli에 commit·일반 push합니다.

## 4. 최초 이관의 사용자 검증과 main 반영

사용자가 yunli의 전체 이관 결과를 검증합니다. 필요한 보완 후 승인된 결과를 main에 반영·push합니다. 기존 사용자 변경과 Linux 원본을 보존합니다. 게시 후 복구는 검토된 revert를 사용합니다.

## 5. 이관 이후 최적화

전체 이관과 사용자 검증 이후 실제 사용 사례를 기준으로 최적화를 진행합니다. 스킬 생략·축약·통합·모델/MCP 변경을 이번 이관의 완료 조건으로 적용하지 않습니다. 실제 홈 적용과 발견은 별도 상태로 기록합니다.

## 6. 이전 작업 자료 정리

현재 적용 지침·기존 변경 확인 → 담당 기록·전체 bytes·Git 제외 보존 → 개인 업데이트와 Windows 개발 기록의 역할에 맞춰 이동 → 링크·도구 경로·이전 안내 갱신 → 전후 해시·기존 변경·개인 설치본 보존 검증 순서로 진행합니다. 과거 PLAN·관찰 JSON을 현행 상태 원본에 덮어쓰지 않습니다. PCS·PCR 이관의 결과·복구 근거는 [SMA 기록](records/2026-10-04-record-relocation-SMA-20261004-01/README.md)에 둡니다.

## 7. LC-PUB-20261004-01 당시 yunli 게시 정책

개인 AGENTS의 상시 완료 절차를 검증·기록 → 담당 변경만 yunli commit·일반 push → 원격 SHA 확인·사용자 commit 링크 보고로 정리합니다. work-rules와 git-commit-rule의 Windows 실행 본문을 맞추고 기존 전체 폴더·로컬 경로 안내를 보존한 뒤 관리 원본 검증 → 로컬 반영 → 담당 파일만 게시 순서로 진행합니다. main·force push·release·운영 적용은 포함하지 않습니다. [업데이트·검증·복구 기록](../2026-10-04-yunli-publication-LC-PUB-20261004-01/README.md)을 따르며 새 세션 행동 검증은 TODO에 유지합니다.

## 8. FC-20261004-01 문서별 fact-check 추가

현재 사용자 요청은 `PLAN TODO $fact-check`로 PLAN과 TODO 각각의 전체 사실 주장을 검증하는 스킬 추가입니다. 기존 스킬·Kiro 프롬프트를 보존하고 독립된 `fact-check`를 작성 → 메타데이터·문서·격리된 기본 수정/수정 금지 행동 검증 → 담당 파일만 yunli 게시 순서로 생성본을 준비합니다. 기본은 확인된 오류 수정·재검증이며 명시적 편집 제한이면 검토만 수행하고 추론과 일반 작업 상태 감사로 확대하지 않습니다. 사용자가 로컬 적용 대기를 요청했으므로 설치는 수행하지 않습니다. [생성·검증·복구 기록](../2026-10-04-fact-check-FC-20261004-01/README.md)에 결과와 적용 대기 상태를 구분하며, 후속 적용 요청 시 기존 사본·설정을 다시 대조한 뒤 새 폴더만 반영합니다.

후속 FC-20261004-02는 사용자가 제안한 대상 문서 추가·수식 금지, 도구 확인, ✅ / ❌ / 🟡 항목별 보고, 오류 diff, 최대 2회 반복과 최종 집계를 반영합니다. 기존 출처·조건·근거 필요 표시 추가 허용을 제거하고 출처는 보고에만 남깁니다. [보완·검증·복구 기록](../2026-10-04-fact-check-rules-FC-20261004-02/README.md)에서 생성본 검증과 로컬 적용 대기를 구분합니다.
