# FC-20261004-01 fact-check 생성·검증

## 1. 범위와 변경

- 관리 원본: `codex_windows/skills/fact-check/`의 `SKILL.md`와 `agents/openai.yaml` 두 파일입니다. 별도 실행 스크립트·중앙 저장소·형제 스킬 설치를 요구하지 않습니다.
- 현재 스킬과 [Kiro fact-check 프롬프트](../../../kiro/prompts/fact-check.md)를 참고하되 보존 원본·기존 19개 스킬은 편집하지 않습니다. 최초 이관 19개와 추가 1개를 구분하여 현재 Windows 배포 안내를 20개로 갱신합니다.
- 담당 문서는 root README·CHANGELOG, Windows 구조·배포·스킬 목록, [PLAN](../windows/PLAN.md)·[TODO](../windows/TODO.md), 이 기록과 [검증 결과](validation.json)입니다.
- 32번 스킬 목록은 당시 세션의 스냅샷이므로 이번 작업에서 변경하지 않습니다. Linux·Kiro·GPT 보존본, 개인 AGENTS·config, system·plugin, 게임 환경도 범위 밖입니다.

## 2. 호출과 동작

```text
PLAN TODO $fact-check
PLAN TODO "$fact-check" 수정 금지
$fact-check PLAN.md TODO.md
```

각 문서 전체를 독립적으로 검증합니다. PLAN·TODO가 역할명으로 주어지면 대상 repo의 실제 적용 지침이 지정한 현행 파일을 찾으며 과거 기록·템플릿·다른 환경 파일로 확대하지 않습니다.

기본 호출은 근거로 확정된 오류만 최소 수정하고 재검증합니다. `수정 금지`, `검토만`, `읽기 전용`은 모든 편집을 제한합니다. **추론 금지**를 명시하여 원문·기록·관찰의 대조와 확인된 입력의 산술 검증만 사용하고, 원인·의도·상태·지원 범위를 추측으로 채우지 않습니다.

계획·요구사항·의견·역사 기록과 현재 사실을 구분합니다. 체크박스는 문서의 표시·집계 기준으로 확인하며 실제 작업 성공을 추론하지 않습니다. 근거가 없는 주장과 누락된 로그는 미확인으로 남기고 자동 삭제하지 않습니다. 문서 간 대조는 개별 주장의 근거 확인에 필요한 경우에 한하며 일반 작업 상태 감사로 확대하지 않습니다.

## 3. 검증과 미실행

현재 검사 결과는 [validation.json](validation.json)에 기록합니다. 원형 개인 자료·명령 출력·격리 시험 입력·전후 사본은 Git 제외 `private/`에 보존합니다.

초기 Luna 격리 시험에서 기본 호출은 포트·완료율 두 오류만 수정하고, 수정 금지 호출은 파일을 변경하지 않았습니다. 초기 검토의 주장 수 집계와 체크박스 상태 해석이 서로 달라 주장 분리·중복 집계와 문서 표시/실제 수행 구분을 보완했습니다. 별도 격리 사본의 재시험에서도 수정 범위와 읽기 전용 보존을 확인했습니다. 재시험 중 한 검토가 예정과 현재 미적용 주장을 함께 제외한 사례가 있어, 같은 줄의 예정/현재 주장 분리 규칙을 추가하고 후속 범위 검토를 수행합니다. 이전 시험과 누락 관찰은 보존하며 코드·메타데이터 검사만으로 의미 검증 완료를 주장하지 않습니다.

검증은 메타데이터·Markdown·비밀값·범위 보존과 격리된 명시 경로 행동 시험입니다. 외부 기술 주장 검색·새 세션의 자동 발견·자동 선택·실제 프로젝트 전체의 사실 검증은 이번 생성 시험의 통과 범위에 포함하지 않습니다.

**로컬 설치·개인 설정 변경·main 병합·force push·release·운영 적용은 미실행**입니다. 검토한 생성본은 상시 승인 범위의 yunli commit·일반 push로 제공하며 정확한 게시 결과는 Git 기록과 최종 사용자 보고를 따릅니다.

## 4. 확인 후 적용과 복구

현재 사용자의 적용 대기 요청을 유지합니다. 이후 적용 요청 시 실제 로컬의 동명 폴더·사용자 차이·설정을 다시 확인하고 작업별 새 비공개 백업을 만든 뒤, 검증한 `fact-check` 폴더만 지원되는 사용자 스킬 위치에 반영합니다. 이번 생성 시점의 백업을 미래 설치 직전 상태로 간주하지 않습니다.

폴더 단위 복사 후 원본/설치본 파일 목록·SHA-256을 대조하고 기존 스킬·설정의 보존을 확인합니다. 새 세션의 발견·호출·실제 행동은 별도로 관찰합니다. 현재 배치는 설치 완료나 자동 발견의 증거가 아닙니다.

미게시 생성본의 복구는 담당 파일의 `private/before/owned/` 사본과 현재 변경을 대조하여 이번 변경만 되돌립니다. 신규 스킬 폴더는 기존 사용자 변경 유무를 확인한 뒤 처리합니다. 게시 후 복구는 검토한 revert로 진행하며 개인 적용은 아직 없어 로컬 제거 작업이 필요하지 않습니다.
