# 보라색 예정 표시 반영

## 1. 범위와 의미

T-WIN-004 후속으로 사용자가 보라색 원을 예정 작업에 사용하도록 요청했습니다. 🟣 예정은 앞으로 진행할 작업·아직 시작하지 않은 다음 단계입니다. 실행 승인이나 선행 조건 충족을 뜻하지 않습니다. 기존 상태 7개와 별점·보조 기호의 의미를 유지합니다.

개인 [AGENTS](../../../codex_windows/AGENTS.md), [work-rules](../../../codex_windows/skills/work-rules/SKILL.md), 현행 소비자 7개의 STYLE·검사기를 함께 반영했습니다. 비교용 originals·Linux·과거 검증 기록은 수정하지 않았습니다.

## 2. 보존과 설치

관리 원본 수정 전에 기존 설치본 3개 폴더와 개인 AGENTS의 전체 사본·해시를 이번 private에 보존했습니다. 설치본의 실제 내용 차이는 없었습니다. work-rules·git-commit-rule·md-link-check의 전체 배포 폴더를 반영했으며 기존 캐시와 개인 경로 부록을 보존했습니다. 미설치 skill을 새로 설치하지 않았습니다.

내용 파일 80개의 source/installed 목록·해시가 일치합니다. 기존 캐시 3개를 포함한 설치 폴더의 전체 파일 집합과 내용 파일 집합을 구분합니다. 개인 AGENTS는 승인된 상태 문구 이외의 bytes를 유지했습니다.

## 3. 검증

- [원본 회귀](regression.json): 실제 검사기 7개·462개 검사 통과.
- [설치본 회귀](installed-regression.json): 실제 검사기 3개·198개 검사 통과.
- [시험 코드](test_purple_policy.py)는 기존 허용·거부·원문 보존 시험을 재사용하고 보라색 허용·표시 선택자·공백·실제 CLI 종료 상태를 추가합니다.
- 문서·구조·동일 사본·담당 해시 검사는 [집계](validation.json)에 기록합니다. 기존 STYLE 진단과 이번 추가 진단을 구분합니다.

첫 시험은 Windows 임시 폴더의 접근 제한으로 실패했습니다. 작업 폴더의 상속 권한을 사용하는 시험 사본으로 원인을 보정했으며 OS 권한이나 설정은 변경하지 않았습니다. 첫 구조 검사에서 기본 Python의 YAML 의존성이 없어 실패했으며 후속 결과와 구분합니다.

## 4. 복구와 미확인

발견 경로 밖의 이번 private/before에서 설치 폴더·개인 AGENTS를 복구할 수 있습니다. 복구 전에 이후 사용자 변경을 대조하고 이번 변경만 선택 복원합니다. 게시 후 원본 복구는 검토한 revert를 사용합니다.

지정 설치·해시 일치·검사기 행동과 독립 새 세션의 암묵 선택·장기 보고 행동은 구분합니다. 후자는 기존 T-WIN-004 후속에서 유지합니다. Goal·앱 테마·알림 표시·config·자동 감시는 변경하지 않았습니다. Git 게시 상태는 단일 통합 담당의 실제 commit·원격 SHA로 확인합니다.
