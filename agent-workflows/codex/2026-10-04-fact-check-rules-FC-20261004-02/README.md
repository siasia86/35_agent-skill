## 1. 범위와 변경

작업 ID는 `FC-20261004-02`입니다. 담당 파일은 `codex_windows/skills/fact-check/SKILL.md`, [Windows PLAN](../windows/PLAN.md)·[TODO](../windows/TODO.md), root CHANGELOG, 이 기록과 [validation.json](validation.json)입니다. UI 메타데이터, 다른 스킬·Kiro·Linux·GPT 보존본, 개인 설정, 게임 저장소는 수정하지 않습니다.

기존 생성본은 출처·조건·근거 필요 표시를 대상 문서에 덧붙일 수 있었습니다. 이번 요청에 맞춰 이 허용을 제거하고, 대상 문서는 근거로 확정된 기존 오류 구간만 최소 교체하도록 변경합니다. 출처·확인일·검증 설명은 보고에만 남깁니다. 미확인 항목의 삭제·윤문·추론 보완은 금지합니다.

공식/로컬 원문은 반드시 실제 도구로 확인합니다. 사용자 예시인 `lynx`·`curl`·`grep`과 현재 환경의 브라우저·문서 조회·파일 읽기·`rg`를 동등한 확인 수단으로 명시하여 특정 프로그램 설치를 새 선행 조건으로 만들지 않습니다.

## 2. 호출과 결과 계약

```text
PLAN TODO $fact-check
PLAN TODO "$fact-check" 수정 금지
```

문서 각각의 전체 사실 주장을 검증하는 범위는 유지합니다. 항목별 ✅ 확인됨 / ❌ 불일치 / 🟡 미확인·판단 필요를 한국어로 표시하고, ❌ 항목은 실제 확인한 출처를 반드시 병기합니다. ✅ 항목의 출처는 보고에서 생략할 수 있으나 실제 도구 확인은 생략할 수 없습니다. 로컬 주장은 실제 근거 파일·줄번호도 출처로 사용합니다.

한 번의 반복은 사실 추출·근거 대조 → 오류만 최소 수정 → 재검증 → 잔여 이슈 확인입니다. 최초 반복을 포함해 최대 2회이며 새 근거로 확정된 잔여 오류가 있을 때만 두 번째 반복을 수행합니다. 수정 금지이면 수정 단계와 수정 후 재검증을 생략합니다.

수정했다면 오류 부분의 diff를 표시합니다. 최종 요약은 문서별 검증 수, 마지막 검증의 정확 수, 수정 수, 잔여 ❌ / 🟡 항목의 수와 내용, 실제 반복 수를 포함합니다. 수정 전·후 판정은 같은 주장 단위로 집계하여 수정된 오류를 중복으로 세지 않습니다.

## 3. 검증과 미실행

현재 검사 결과는 [validation.json](validation.json)에 기록합니다. 전체 개인 스킬·설정 사본, 원본·변경 전후 해시, 명령 출력과 격리 행동 시험은 Git 제외 `private/`에 보존합니다. 검증 도구의 버전·검사 대상·실패와 보완은 실제 결과로 구분합니다.

격리 기본 수정 3회·수정 금지 2회는 실제 선택한 `gpt-6-luna`에 명시 경로로 스킬을 제공하여 수행했습니다. 서로 다른 fixture에 담당 범위를 분리했고 main이 파일별 변경과 근거·보고를 대조합니다. 각 신규 호출의 실제 검증 반복은 1회이며, 개발 중의 독립 시험 호출 수를 한 호출의 반복 수로 합치지 않습니다.

첫 수정 시험은 대상 두 오류만 고쳤지만 보고에서 한 수정 전 판정이 빠졌고 diff를 화살표로 표시했습니다. 읽기 전용 시험의 중간 총수는 7에서 실제 주장 6으로 정정되었습니다. 두 번째 수정 시험은 diff를 표시했으나 완료율 오류에 명시적 출처 경로가 빠졌습니다. 모든 수정의 수정 전·후 판정, diff 코드블록, 출력 전 출처·집계 확인을 보완한 마지막 시험은 두 오류의 실제 출처와 diff·재검증 결과를 모두 표시했습니다. 표현을 꾸미는 행위와 확인 입력의 산술 검증도 구분했습니다. 앞선 누락·정정은 성공한 마지막 결과로 덮어쓰지 않습니다.

마지막 수정 시험의 결과는 PLAN 4건·TODO 2건 중 정확 3건, 수정 2건, 잔여 미확인 3건입니다. 마지막 읽기 전용 시험은 같은 6건 중 정확 1건, 수정 0건, 잔여 불일치 2건·미확인 3건으로 보고했습니다. 계획·미확인 내용·근거 파일은 보존하며, 최종 파일 bytes 대조 결과는 검증 JSON에 기록합니다.

최초 Markdown 스타일 검사는 기호 뒤 간격 오류 23건으로 실패했습니다. 담당 문구의 간격만 교정하고 검사 제외 옵션 없이 재검증합니다. 메타데이터·Markdown·로컬 링크/교차 앵커·비밀값·기존 개인 스킬 및 설정 보존의 실제 결과는 validation JSON과 비공개 명령 로그로 구분합니다.

교차 앵커 보완 검사의 첫 집계는 0건이었으나 대상 문서에 실제 교차 링크가 있어 미완료로 판정했습니다. 파일 링크용 helper가 앵커를 제거하는 동작을 확인하고, 원시 목적지의 앵커를 실제 헤딩과 대조하도록 이번 비공개 검증 스크립트를 교정했습니다. 0건 결과를 앵커 검사 통과로 처리하지 않습니다.

외부 기술 주장 검색, 최대 반복에 실제 도달하는 실패 상황, 새 세션의 자동 발견·선택, 실제 프로젝트 전체 사실 검증은 이 격리 시험과 구분합니다. **로컬 설치·개인 설정 변경·main 병합·force push·release·운영 적용은 수행하지 않습니다.** 담당 변경은 상시 승인된 yunli commit·일반 push 범위로 제공하며 정확한 게시 결과는 Git 기록과 최종 보고를 따릅니다.

## 4. 적용 대기와 복구
